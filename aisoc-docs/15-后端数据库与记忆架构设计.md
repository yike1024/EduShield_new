# Part A：数据库架构设计

## 1. 技术选型建议

| 方案 | 适用场景 | 推荐度 | 理由 |
|------|----------|--------|------|
| **PostgreSQL 16** | 生产环境、多用户并发 | ⭐⭐⭐ 推荐 | ACID 事务、JSONB 存对话元数据、全文检索（pg_trgm）、成熟生态 |
| **SQLite + WAL** | 单机部署、轻量场景 | ⭐⭐ 备选 | 零配置、单文件，但并发写入受限 |
| **Redis** | 会话缓存、短期记忆 | 辅助层 | 高速 KV，用作 token 黑名单、活跃对话上下文缓存 |

**推荐架构**：PostgreSQL（持久化主库）+ Redis（缓存层），大脑已有 FastAPI 异步框架天然适配 asyncpg/SQLAlchemy async。

## 2. 用户表设计

### 2.1 `users` 表

```sql
CREATE TABLE users (
    -- 主键与标识
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    username        VARCHAR(20)  NOT NULL UNIQUE,
    email           VARCHAR(255) NOT NULL UNIQUE,
    phone           VARCHAR(20)  UNIQUE,                    -- 可选，手机号
    -- 认证
    password_hash   VARCHAR(255) NOT NULL,                  -- bcrypt(passlib) 哈希
    salt            VARCHAR(64)  NOT NULL DEFAULT gen_salt(),-- 每用户独立盐
    -- 状态
    status          VARCHAR(16)  NOT NULL DEFAULT 'active', -- active | suspended | deleted
    email_verified  BOOLEAN      NOT NULL DEFAULT false,
    role            VARCHAR(16)  NOT NULL DEFAULT 'user',  -- user | admin
    -- 时间戳
    created_at      TIMESTAMPTZ  NOT NULL DEFAULT now(),
    last_login_at   TIMESTAMPTZ,
    last_login_ip   INET,                                   -- 审计用
    -- 偏好（JSONB 灵活字段，对应前端 localStorage 偏好）
    preferences     JSONB        NOT NULL DEFAULT '{}'::jsonb,
    -- 软删除
    deleted_at      TIMESTAMPTZ
);

-- 索引
CREATE INDEX idx_users_username_lower ON users (lower(username));
CREATE INDEX idx_users_email_lower    ON users (lower(email));
CREATE INDEX idx_users_status         ON users (status) WHERE deleted_at IS NULL;
```

**字段对照（前端 → 后端）**

| 前端 `lib/auth.ts` 字段 | 后端表字段 | 说明 |
|--------------------------|------------|------|
| `id` | `id` (UUID) | 前端用 `u_` 前缀短 ID，后端用 UUID；登录后用后端 UUID 替换 |
| `username` | `username` | 3-20 位，校验规则一致 |
| `email` | `email` | 唯一约束 |
| `passwordHash` (SHA-256) | `password_hash` (bcrypt) | **后端必须用 bcrypt 替代 SHA-256**，见 §2.2 |
| `createdAt` | `created_at` | ISO 8601 |
| —（前端无） | `phone` | 后端新增，前端注册表单可选扩展 |
| —（前端无） | `last_login_at` | 登录时更新 |
| —（前端无） | `status` | 账户状态控制 |

### 2.2 密码存储安全要求

> 前端 `auth.ts` 当前用 SHA-256（纯前端限制下的妥协），**后端必须用 bcrypt**。

```python
# Python 示例（passlib）
from passlib.context import CryptContext
pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

hashed = pwd_context.hash(password)      # 注册时
verified = pwd_context.verify(password, stored_hash)  # 登录时
```

| 要求 | 说明 |
|------|------|
| 哈希算法 | bcrypt（cost=12）或 argon2id |
| 盐 | bcrypt 自动生成，无需单独 `salt` 列（盐可保留做二次 HMAC） |
| 禁止明文 | 任何日志、响应、缓存中均不得出现明文密码 |
| 前端到后端传输 | HTTPS + 请求体，**前端不做哈希**，传明文密码给后端（TLS 保护） |

> **迁移策略**：前端 `authApi` 的 `login/register` 方法改为 `fetch('/api/auth/login')` 后，密码以明文经 HTTPS 传给后端，后端 bcrypt 哈希存储。前端 `auth.ts` 的 SHA-256 逻辑删除。

### 2.3 会话管理表

```sql
CREATE TABLE sessions (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id         UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    token_hash      VARCHAR(255) NOT NULL UNIQUE,  -- 存 token 的 SHA-256 哈希，不存原文
    remember_me     BOOLEAN NOT NULL DEFAULT false,
    expires_at      TIMESTAMPTZ,                    -- NULL = 永久
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    revoked_at      TIMESTAMPTZ                     -- 注销时设置
);

CREATE INDEX idx_sessions_user    ON sessions(user_id) WHERE revoked_at IS NULL;
CREATE INDEX idx_sessions_token  ON sessions(token_hash);
```

**Token 设计**：
- 生成：`secrets.token_urlsafe(32)`
- 存储：后端只存 `SHA-256(token)` 的哈希，泄露数据库也无法直接复用
- 下发：HTTP-Only Cookie + 响应体 `{ token: "..." }` 双通道
- 前端：存 `localStorage['edushield:session']`（remember）或 `sessionStorage`（不 remember）

## 3. 历史对话表设计

### 3.1 表结构

```sql
-- 对话表：一次完整对话（一个 tab / 一个 topic）
CREATE TABLE conversations (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id         UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    -- 标识
    title           VARCHAR(500) NOT NULL DEFAULT '新对话',
    domain          VARCHAR(32),             -- pentest / logaudit / incident / intel / chat
    tab_id          VARCHAR(64),             -- 前端 tab 标识，用于跨页面恢复
    -- 状态
    status          VARCHAR(16) NOT NULL DEFAULT 'active', -- active | archived | deleted
    pinned          BOOLEAN NOT NULL DEFAULT false,
    -- 摘要（由记忆系统生成，见 Part B §7）
    summary         TEXT,                    -- 自动摘要（≤500 字）
    summary_updated_at TIMESTAMPTZ,
    -- 元数据
    message_count   INTEGER NOT NULL DEFAULT 0,
    token_count     INTEGER NOT NULL DEFAULT 0,    -- 累计 token
    -- 时间戳
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_conv_user       ON conversations(user_id, updated_at DESC) WHERE status != 'deleted';
CREATE INDEX idx_conv_user_pinned ON conversations(user_id, pinned DESC, updated_at DESC) WHERE status = 'active';
CREATE INDEX idx_conv_tab        ON conversations(tab_id) WHERE tab_id IS NOT NULL;
```

```sql
-- 消息表：对话内的每一条消息（用户提问 / AI 回答 / 工具调用 / 系统通知）
CREATE TABLE messages (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    conversation_id UUID NOT NULL REFERENCES conversations(id) ON DELETE CASCADE,
    user_id         UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    -- 内容
    role            VARCHAR(16) NOT NULL,     -- user | assistant | tool | system
    content         TEXT NOT NULL,           -- 正文（Markdown）
    reasoning       TEXT,                    -- 推理过程（CoT，可空）
    -- 工具调用（role=tool 时填充）
    tool_name       VARCHAR(128),
    tool_args       JSONB,                    -- 工具参数
    tool_output     TEXT,                     -- 工具输出
    tool_exit_code  INTEGER,
    -- 元数据
    token_count     INTEGER,                  -- 该消息 token 数
    model           VARCHAR(64),              -- 使用的模型
    -- 向量化（用于长期记忆检索，见 Part B §7）
    embedding_id    BIGINT,                   -- pgvector 向量 ID
    importance      SMALLINT NOT NULL DEFAULT 0, -- 0-100，记忆重要性评分
    -- 时间戳
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    sequence_num    INTEGER NOT NULL          -- 对话内序号
);

CREATE INDEX idx_msg_conv_seq   ON messages(conversation_id, sequence_num);
CREATE INDEX idx_msg_user_time  ON messages(user_id, created_at DESC);
CREATE INDEX idx_msg_importance ON messages(user_id, importance DESC) WHERE importance >= 60;
```

### 4.6 前端切换指南

```typescript
// lib/auth.ts — authApi 切换为 HTTP 调用
export const authApi = {
  async register(username, email, password, confirmPassword) {
    const res = await fetch('/api/auth/register', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ username, email, password, confirmPassword }),
    });
    if (!res.ok) throw new AuthException((await res.json()).code);
    return res.json();
  },
  async login(identifier, password, remember) {
    const res = await fetch('/api/auth/login', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ identifier, password, remember }),
    });
    if (!res.ok) throw new AuthException((await res.json()).code);
    const data = await res.json();
    // token 存 localStorage/sessionStorage（与当前逻辑一致）
    const storage = remember ? localStorage : sessionStorage;
    storage.setItem('edushield:session', JSON.stringify({
      userId: data.user.id, token: data.token, expiresAt: data.expiresAt, issuedAt: Date.now()
    }));
    return data;
  },
  // ...
};
```

# Part B：模型记忆能力实现路径

## 6. 上下文管理策略

### 6.1 三层上下文架构

```
┌─────────────────────────────────────────────────────────┐
│  Layer 1：工作记忆（Working Memory）                     │
│  当前对话窗口内的最近 N 条消息，直接注入 LLM prompt        │
│  大小：4K-8K tokens（可配置）                             │
│  存储：内存 / Redis（活跃对话缓存）                       │
├─────────────────────────────────────────────────────────┤
│  Layer 2：对话摘要（Conversation Summary）                │
│  当前对话历史超出窗口部分的压缩摘要                        │
│  大小：500-1000 tokens                                   │
│  存储：conversations.summary + messages 表               │
│  触发：消息数超过窗口阈值时自动生成                        │
├─────────────────────────────────────────────────────────┤
│  Layer 3：长期记忆（Long-Term Memory）                    │
│  跨对话的重要信息，向量化检索                              │
│  存储：pgvector + messages.embedding                     │
│  触发：每轮对话结束后异步提取并入库                        │
└─────────────────────────────────────────────────────────┘
```

### 6.2 上下文窗口大小设置

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| `WORKING_WINDOW_MESSAGES` | 12 | 工作记忆保留的最近消息数（6 轮对话） |
| `WORKING_WINDOW_TOKENS` | 4096 | 工作记忆 token 上限，超过则触发摘要 |
| `SUMMARY_MAX_TOKENS` | 800 | 单次摘要生成的 token 上限 |
| `SUMMARY_TRIGGER_THRESHOLD` | 8 | 消息数超过此值时触发摘要压缩 |
| `LTM_RETRIEVAL_TOP_K` | 5 | 长期记忆检索返回的条数 |

**自适应策略**：

```python
def build_context(conversation_id: str, user_id: str) -> str:
    messages = get_messages(conversation_id, limit=WORKING_WINDOW_MESSAGES + 10)

    if len(messages) <= WORKING_WINDOW_MESSAGES:
        # 未超窗口：直接拼接
        return format_messages(messages)

    # 超窗口：最近 N 条 + 前序摘要
    recent = messages[-WORKING_WINDOW_MESSAGES:]
    summary = get_or_generate_summary(conversation_id, messages[:-WORKING_WINDOW_MESSAGES])

    # 检索长期记忆（基于最近消息语义）
    query_embedding = embed(last_user_message)
    ltm_hits = vector_search(user_id, query_embedding, top_k=LTM_RETRIEVAL_TOP_K)

    return f"""
    [对话摘要] {summary}

    [相关历史记忆]
    {format_ltm_hits(ltm_hits)}

    [最近对话]
    {format_messages(recent)}
    """
```

### 6.3 历史对话摘要机制

**渐进式摘要（Incremental Summarization）**：

```
对话消息 1-8 → 摘要 S1
对话消息 9-16 → 摘要 S1+S2 合并为 S1'
对话消息 17-24 → 摘要 S1'+S3 合并为 S1''
...
```

避免每次全量重算，保持 O(1) 的摘要更新成本。

**摘要 Prompt 模板**：

```
你是一个对话摘要器。请将以下对话内容压缩为不超过 500 字的摘要，
保留：
  1. 用户的核心意图与目标
  2. 关键发现与结论
  3. 未解决的问题与后续计划
丢弃：寒暄、重复内容、工具调用的原始输出细节

[前序摘要] {previous_summary}
[新增对话] {new_messages}
```

**存储**：摘要写入 `conversations.summary`，`summary_updated_at` 记录最后更新时间。

### 6.4 关键信息提取方法

```python
# 在对话结束后异步执行
def extract_key_info(conversation_id: str, user_id: str):
    messages = get_full_conversation(conversation_id)

    prompt = f"""
    从以下对话中提取关键信息，以 JSON 数组返回，每条包含：
    - content: 信息内容
    - type: fact | preference | goal | entity | skill
    - importance: 0-100
    - keywords: [关键词列表，用于检索]

    对话内容：
    {format_messages(messages)}
    """

    result = await llm_call(prompt, response_format="json")
    for item in result:
        # 向量化并存入长期记忆
        embedding = await embed(item["content"])
        store_memory(user_id, conversation_id, item, embedding)
```

| 信息类型 | 提取规则 | importance 范围 |
|----------|----------|-----------------|

## 7. 长期记忆存储方案

### 7.1 表结构

```sql
-- 需安装 pgvector 扩展：CREATE EXTENSION vector;

CREATE TABLE memory_entries (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id         UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    conversation_id UUID REFERENCES conversations(id) ON DELETE SET NULL,
    -- 内容
    content         TEXT NOT NULL,               -- 记忆内容
    type            VARCHAR(16) NOT NULL,        -- fact | preference | goal | entity | skill
    importance      SMALLINT NOT NULL DEFAULT 50,-- 0-100
    keywords        TEXT[],                      -- 关键词数组
    -- 向量（pgvector，768 维适配 bge-small-zh / text-embedding-3-small）
    embedding       vector(768),
    -- 生命周期
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    last_accessed_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    access_count    INTEGER NOT NULL DEFAULT 0,
    decay_score     REAL NOT NULL DEFAULT 1.0,   -- 衰减分数，见 §9
    -- 状态
    status          VARCHAR(16) NOT NULL DEFAULT 'active', -- active | forgotten | merged
    superseded_by   UUID REFERENCES memory_entries(id), -- 被新记忆覆盖时指向替代
    -- 来源
    source          VARCHAR(32) NOT NULL DEFAULT 'extracted' -- extracted | user_marked | system
);

-- 向量索引（HNSW 优于 IVFFlat，适合中小规模）
CREATE INDEX idx_mem_user_embedding ON memory_entries
    USING hnsw (embedding vector_cosine_ops)
    WHERE status = 'active';

CREATE INDEX idx_mem_user_type       ON memory_entries(user_id, type, importance DESC);
CREATE INDEX idx_mem_user_keywords   ON memory_entries USING gin(keywords);
CREATE INDEX idx_mem_user_recent     ON memory_entries(user_id, last_accessed_at DESC);
```

### 7.2 检索流程

```python
async def retrieve_long_term_memory(
    user_id: str,
    query: str,
    top_k: int = 5,
    min_importance: int = 40,
) -> list[MemoryEntry]:
    # 1. 向量化查询
    query_vec = await embed(query)

    # 2. 向量检索 + 过滤
    results = await db.fetch_all("""
        SELECT *, 1 - (embedding <=> $1) AS similarity
        FROM memory_entries
        WHERE user_id = $2
          AND status = 'active'
          AND importance >= $3
          AND decay_score > 0.3
        ORDER BY embedding <=> $1
        LIMIT $4
    """, query_vec, user_id, min_importance, top_k)

    # 3. 关键词补充检索（向量 miss 的精确匹配）
    keywords = extract_keywords(query)
    keyword_hits = await db.fetch_all("""
        SELECT * FROM memory_entries
        WHERE user_id = $1 AND status = 'active'
          AND keywords && $2::text[]
          AND id NOT IN (SELECT unnest($3::uuid[]))
        ORDER BY importance DESC
        LIMIT 3
    """, user_id, keywords, [r["id"] for r in results])

    # 4. 更新访问记录（反馈循环）
    for r in results + keyword_hits:
        await touch_memory(r["id"])

    return results + keyword_hits
```

### 7.3 记忆写入时机

| 时机 | 触发条件 | 操作 |
|------|----------|------|
| 对话结束 | SSE `[DONE]` 帧 | 异步执行 §6.4 关键信息提取，写入 `memory_entries` |
| 用户标记 | 用户在 UI 点"记住这条" | 直接写入，`importance=100`，`source='user_marked'` |
| 摘要生成 | 消息数超阈值 | 摘要本身存 `conversations.summary`，关键事实额外提取到 `memory_entries` |
| 偏好检测 | 检测到模式化选择（见 §8.3） | 写入 `type='preference'` |

### 7.4 向量化模型选择

| 模型 | 维度 | 语言 | 部署方式 | 推荐度 |
|------|------|------|----------|--------|
| `bge-small-zh-v1.5` | 512 | 中文优 | 本地 sentence-transformers | ⭐⭐⭐ |
| `text-embedding-3-small` | 1536 | 中英 | OpenAI API | ⭐⭐ |
| `bge-m3` | 1024 | 多语言 | 本地 | ⭐⭐ |

推荐 `bge-small-zh-v1.5`：512 维够用，本地部署零成本，中文检索效果好。表结构 `vector(768)` 可按实际模型调整。

## 9. 记忆更新与遗忘机制

### 9.1 衰减模型

采用 **Ebbinghaus 衰减变体** + **访问强化**：

```python
def calculate_decay_score(memory: MemoryEntry) -> float:
    """
    衰减分数 = base_decay * reinforcement_factor

    base_decay: 随时间指数衰减
    reinforcement_factor: 每次访问增强（访问越频繁越不容易忘）
    """
    age_hours = (now() - memory.created_at).total_seconds() / 3600
    access_factor = min(memory.access_count, 10) / 10  # 上限 10 次

    # 基础衰减（半衰期 14 天）
    base_decay = math.exp(-0.693 * age_hours / (14 * 24))

    # 强化因子（访问过的记忆衰减更慢）
    reinforcement = 1.0 + 0.5 * access_factor

    # 重要性加权（高重要性衰减更慢）
    importance_factor = 0.5 + (memory.importance / 100) * 0.5

    return min(base_decay * reinforcement * importance_factor, 1.0)
```

### 9.2 遗忘策略

| 衰减分数 | 操作 | 说明 |
|----------|------|------|
| > 0.7 | 无操作 | 活跃记忆，正常检索 |
| 0.3 - 0.7 | 降低权重 | 检索排序降权，`importance` 等效降低 |
| 0.1 - 0.3 | 标记候选 | 进入遗忘候选池，等待合并或清除 |
| < 0.1 | 归档 | `status='forgotten'`，不再参与检索 |

### 9.3 记忆合并

当检测到同一主题的多条相似记忆时，执行合并：

```python
async def merge_memories(user_id: str):
    """定期任务（每日）"""
    # 1. 找出同一 type + keywords 高重叠的记忆组
    clusters = await cluster_similar_memories(user_id, threshold=0.85)

    for cluster in clusters:
        if len(cluster) < 2:
            continue

        # 2. LLM 合并
        prompt = f"""
        将以下 {len(cluster)} 条记忆合并为 1 条，保留所有关键信息：
        {format_memories(cluster)}
        """
        merged = await llm_call(prompt)

        # 3. 创建新记忆，标记旧记忆为已替代
        new_id = await create_memory(user_id, merged, ...)
        await db.execute("""
            UPDATE memory_entries
            SET status='merged', superseded_by=$2
            WHERE id = ANY($1::uuid[])
        """, [m["id"] for m in cluster], new_id)
```

### 9.4 显式遗忘

用户主动操作触发：

| 操作 | 效果 |
|------|------|
| 删除对话 | 对话消息从 `messages` 软删除，关联的 `memory_entries` 衰减分数 ×0.1 |
| "忘记这条" | 单条 `memory_entries.status='forgotten'` |
| 清空记忆 | 该用户所有 `memory_entries.status='forgotten'` |
| 修改偏好 | 旧偏好 `status='merged'`，新偏好 `importance=100` |

### 9.5 定时任务

```python
# Cron / APScheduler
async def memory_maintenance():
    """每日 03:00 执行"""
    # 1. 重新计算所有活跃记忆的衰减分数
    await db.execute("""
        UPDATE memory_entries
        SET decay_score = exp(-0.693 * extract(epoch from now()-created_at)/1209600)
                           * (1.0 + 0.05 * least(access_count, 10))
                           * (0.5 + importance::real/200)
        WHERE status = 'active'
    """)

    # 2. 遗忘低分记忆
    await db.execute("""
        UPDATE memory_entries SET status='forgotten'
        WHERE status='active' AND decay_score < 0.1 AND importance < 70
    """)

    # 3. 合并相似记忆
```
