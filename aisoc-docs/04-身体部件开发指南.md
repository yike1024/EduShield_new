## 1. 身体部件公式

```
身体部件 = reasonix-core 内核（共享，禁止复制）
        + 领域工具集
        + 领域 SKILL.md 技能
        + 领域报告模板
        + 配置（reasonix.toml 裁剪）
```

**反模式**：每个部件复制一份内核源码（3 个庞大项目 + 3 倍维护）。内核 = 共享 Go module，部件只做薄 shell。

**部件最小包标准**：至少 2 个真实工具 + 1 个技能 + 1 个报告模板，否则并入相邻部件。

## 2. 目录骨架（新建部件模板）

```
log-audit-agent/
├── go.mod                 # 依赖 reasonix-core（共享 module）
├── cmd/agent/main.go      # 入口：装配领域工具 → cli.Run
├── internal/
│   ├── tools/             # 领域工具（@register 注册）
│   │   ├── log_ingest.go      # 日志接入
│   │   ├── anomaly_detect.go  # 异常检测
│   │   └── correlation.go     # 关联分析
│   ├── skills/            # 领域技能 SKILL.md
│   └── report/            # 领域报告模板
├── reasonix.toml          # 部件专属配置（工具白名单/权限/模型）
└── README.md
```

> 若内核以 module 形式提供：`go.mod` 里 `replace reasonix-core => ../../reasonix-core`（monorepo 场景）或走私有 registry。

## 3. 领域工具开发

以 reasonix 内置工具注册方式为准（`internal/tool/builtin/` 内 `@register` 或等价机制）。参考内置安全工具清单：

| 类别 | 现有工具 | 部件归属 |
|---|---|---|
| 侦察 | port_scan / dns_enum / subdomain_enum / whois_lookup / ssl_check | pentest |
| Web | http_probe / vuln_scan | pentest |
| 漏洞研究 | cve_search / hash_identify | pentest |
| 取证 | forensic_extract | pentest/logaudit |
| 证据管理 | findings / report | 全部（内核） |

**新增工具三要求**：

1. 产出**双轨**：人读字符串 + 结构化 Finding（复用 `evidence.Finding`，含 severity/cve/cwe/cvss/confidence）
2. 遵守权限分级：只读工具自动执行；写入类（封禁/利用/修改）标记需审批
3. 目标校验：工具内部对 target 做授权白名单复查（大脑校验是第一道，工具内是第二道）

## 4. 领域技能（SKILL.md）

技能 = 触发词 + 执行流程。示例（logaudit 部件）：

```markdown
---
name: log-audit
description: 日志审计：接入日志、定位异常、输出审计发现
triggers: [日志审计, 审计日志, log analysis, 异常流量, 可疑IP]
---

# 日志审计流程
1. 用 log_ingest 接入目标日志（支持 nginx/apache/syslog）
2. 用 anomaly_detect 检测：暴力破解/扫描/异常时段/大流量
3. 对命中项用 correlation 关联时间线，输出 Finding
4. 按模板产出审计报告
```

**技能纪律**：流程步骤要**可复现**（固定工具序列），不要自由发挥；涉及外部攻击面（nmap/sqlmap/msf）必须确认目标在授权白名单内。

## 5. 领域报告模板

每部件一份 Markdown 模板，产出前先 `POST /api/knowledge/search` 检索相关规范（等保/OWASP），报告结构：

```
# <域> 报告 — <task_id>
## 摘要（verdict + confidence）
## 发现列表（引用 Finding id，每条含 severity/CVE/证据/修复建议）
## 详细发现（按严重度排序）
## 附录（思维链、工具调用记录、时间线）
```

**注意**：部件的报告是**草稿**；最终报告由大脑汇总生成（报告协议见 02 第 4 节）。

## 6. 部件配置模板（reasonix.toml）

```toml
[sandbox]
bash = "off"          # 默认关沙箱以允许联网工具；如保留沙箱需配置 network

[permissions]
# 只读工具自动执行；写入工具 ask 审批
deny = []             # 部件不需要的工具/命令

[tools]
enabled = ["port_scan", "dns_enum", "cve_search", ...]   # 按领域裁剪
```

> ⚠️ 沙箱取舍：`bash="off"` 使工具可联网（渗透必需），但也失去隔离兜底——**部件实例必须用 --auth token 保护，且 target 必须过授权白名单**（见 06）。若该部件无需联网，建议保留沙箱（`network = "off"` 默认）。

## 7. 渗透部件（身体 A）落地要点

- 现状：12 个内置工具已具备；10 个 CVE 利用技能**未实现**（仅文档声明）——按 P1 只做真实可用的：cve_search 查询 + 验证脚本，不做自动利用
- 外部工具接入：nmap / sqlmap / msf 通过 bash 工具调用（沙箱 off 下可直接调），**先做 nmap 接入 + sqlmap 接入两个真实工具**，满足最小包标准
- 本地 CVE 库：NVD 每日同步 + 本地索引（解决"依赖实时 API"短板）
- 报告：渗透报告模板（发现 + 证据 + 复现步骤）

## 8. 日志审计部件（身体 B）开发要点

- 领域工具（3-5 个，约 3-5k 行）：
  - `log_ingest`：接入 nginx/apache/syslog/自定义格式
  - `anomaly_detect`：暴力破解、端口扫描、异常时段、大流量、webshell 特征
  - `correlation`：多日志关联时间线（入口→横向→外联）
- 技能：日志审计 SKILL.md（见第 4 节示例）
- 产出：审计发现 Finding（含 severity/confidence），上报大脑
- 复用 EduShield 误报抑制规则（爬虫≠攻击、高并发≠DDoS）作为规则轨输入
