## 1. 总体分层

```
┌────────────────────────────────────────────────────────────────────┐
│                    接入层：nginx（外部唯一入口 80/443）              │
│   brain.campus / pentest.campus / audit.campus → 子域名路由          │
└───────┬──────────────────────────┬─────────────────────┬───────────┘
        │                          │                     │
        ▼                          ▼                     ▼
┌──────────────┐      ┌──────────────────┐    ┌──────────────────┐
│ 大脑（1 个）   │      │ 身体部件（N 个）    │    │  共享存储（可选）  │
│ FastAPI 6657  │◄────►│ reasonix 8787/8788│    │  SQLite/对象存储  │
│ 编排·判定·审计  │  HTTP│ ...（端口级隔离）  │    │  (旁路原始数据)   │
└──────────────┘      └──────────────────┘    └──────────────────┘
```

三层职责：

| 层 | 职责 | 禁止事项 |
|---|---|---|
| 接入层 nginx | TLS 终结、子域名路由、限流、请求头注入（X-Forwarded-*） | 不承载业务逻辑 |
| 大脑 FastAPI | 编排调度、威胁判定、知识库、会话管理、审计留档、报告 | 不重写 agent 循环（重试/压缩/子代理） |
| 身体部件 reasonix | 领域执行：推理循环、工具调用、证据产出 | 不直连其他部件、不落库（证据经大脑落库） |

## 2. 物理部署拓扑

```
                外部唯一入口 80/443
                       │ nginx
      ┌────────┬───────┴───────┬────────┐
 brain.campus  pentest.campus  audit.campus  ...
      │             │             │
 127.0.0.1:6657  127.0.0.1:8787  127.0.0.1:8788
  （大脑 FastAPI） （渗透 reasonix） （审计 reasonix）
```

### 2.1 端口规划（部件注册表基线）

| domain | 端口 | 服务 | 状态 |
|---|---|---|---|
| `brain` | 6657 | FastAPI 平台 | 一期 |
| `pentest`（渗透测试） | 8787 | reasonix serve | 一期（现有） |
| `logaudit`（日志审计） | 8788 | reasonix serve（新建） | 一期 |
| `threatintel`（威胁情报） | 8789 | reasonix serve | 二期（可选） |
| `incident`（应急响应） | 8790 | reasonix serve | 二期（可选） |

> 端口分配规则：部件端口从 8787 起顺序分配；新增部件先登记本表再分配，避免冲突。

### 2.2 监听与暴露

- **外部只能访问 nginx（80/443）**；大脑与所有部件实例只监听 `127.0.0.1`
- 实例间通信（大脑→部件）走本机回环，不经 nginx；**经 nginx 的只有外部用户 → 大脑/部件调试页**
- nginx 完整配置见 [05-部署与运维手册](05-部署与运维手册.md)

## 3. 大脑内部模块

```
┌────────────────────────── FastAPI (6657) ──────────────────────────┐
│ Router 层：/api/*（REST） + 前端面板（复用 EduShield static/）        │

│ Orchestrator  编排调度：任务分解/下发/回收/多阶段管道/降级             │

```

## 4. 身体部件通用结构

每个身体部件 = 独立 reasonix serve 实例，内部构成：

```
reasonix serve（127.0.0.1:<port>，--auth token，--behind-proxy）
├── 领域工具集    internal/tool/builtin/ 下按部件裁剪的注册工具
├── 领域技能      skills/<domain>/SKILL.md（触发词 + 流程）
├── 领域报告模板  按部件定制（渗透报告/审计报告）
└── reasonix-core 内核（推理/重试/压缩/子代理/沙箱/证据）——共享不改
```

开发方法见 [04-身体部件开发指南](04-身体部件开发指南.md)。

## 5. 协作模式：星型拓扑

**原则：部件间不建立直接连接；"A 产出 → B 输入"统一表现为大脑发起的两次任务下发。**

```
审计部件 ──Finding(可疑IP+时间线)──▶ 大脑
                                      │ 整理/判定/去重/防误报传播
                                      ▼
渗透部件 ◀──新任务(携带证据摘要)──── 大脑
```

### 5.1 允许的通信通道

| 通道 | 用途 | 是否允许 |
|---|---|---|
| 大脑 → 部件（HTTP submit） | 任务下发 | ✅ 主通道 |
| 部件 → 大脑（HTTP 证据上报） | Finding 回收 | ✅ 主通道 |
| 大脑 → 部件（SSE /events） | 流式接收输出/审批请求 | ✅ 主通道 |
| 部件 → 部件（直连） | 任何数据 | ❌ 禁止 |
| 部件 → 共享存储（写原始数据） | 海量原始数据旁路 | ⚠️ 可选，只写不读他人结论 |
| 部件 → 共享存储（读他人 Finding） | 参考历史证据 | ⚠️ 仅经大脑落库后的只读引用 |

### 5.2 为什么禁止直连

1. **审计完整性**：直连绕过思维链账本，跨域证据流无法追溯，违背"审计留档 180 天"
2. **协议收敛**：N 个部件直连 = O(N²) 接口对；全经大脑 = O(N)
3. **编排可控**：顺序/依赖/降级只有大脑知道全局；直连产生隐式依赖
4. **安全边界**：部件实例互不信任（各配各的 token）

### 5.3 跨域协作流程示例（数据泄露调查）

```
1. 大脑接收任务（task_id=T1，目标=X）
2. 大脑 → logaudit：submit "定位 X 的可疑访问 IP 与时间线"
3. logaudit 经 /events 流式回报 Finding → 大脑落库
4. 大脑判定 → 派发新任务给 pentest（携带审计证据摘要）
5. pentest 验证漏洞 → Finding 回报 → 大脑交叉验证
6. 大脑 verdict=真实泄露，出完整报告（含跨域证据链）
```

## 6. 关键架构决策（ADR）

| # | 决策 | 理由 | 反模式（禁止） |
|---|---|---|---|
| ADR-1 | 一部件一实例一端口 | /events 全局广播需实例级隔离；配置/权限按部件独立；故障隔离 | 单实例多命令级混跑 |
| ADR-2 | nginx 单入口 + 子域名路由 | 对外收敛单端口；serve 资源是根路径绝对地址，路径前缀会断 | 开放多个外部端口 |
| ADR-3 | 星型拓扑，禁止部件直连 | 审计完整/协议收敛/编排可控/安全边界 | 部件间点对点 API |
| ADR-4 | 大脑不重写 agent 循环 | 重试/压缩/子代理等工业级能力不值得用 Python 重写 | 在 FastAPI 内实现 agent 循环 |
| ADR-5 | 实例间用 --auth token 双向互信 | 防绕过 nginx 后直入实例 | 无鉴权裸实例 |
| ADR-6 | 判定走规则+LLM 双轨 | 控制 LLM 幻觉，可校准误报/漏报率 | 纯 LLM 文本判定 |
