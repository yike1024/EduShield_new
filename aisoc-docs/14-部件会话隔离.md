## 1. 业务诉求

**问题**：当前架构下前端开多个 tab / 重进 dashboard，后端的部件（8786 / 8788 / 8789 reasonix）**全部串到同一个会话**：
- 上一次对话历史污染新会话
- 上下文累积可能撑爆窗口
- 任务上下文残留（"继续上次"）

**期望行为**（按前端 session 隔离部件会话）：

| 场景 | 期望行为 |
|---|---|
| 前端会话 A 首次发任务 T1 | 部件开新会话（清空上下文）→ 缓存 `(A, domain)` |
| 前端会话 A 内 T2 | **复用**部件会话（不调 `/new`）→ 部件保留 T1 上下文 |
| 前端从 A 切到 B，发任务 T1' | 部件开新会话（清空 A 残留上下文）→ 缓存 `(B, domain)` |
| 前端不传 `session_id`（旧调用方） | 退化到当前行为（每次任务开新会话） |

**前端标识 session_id 的方式**：进入 `AisocDashboard` 时生成一次稳定的 `chatSessionId = "aisoc-session-{ts}-{rand}"`，mount 期间所有任务共用；刷新页面 / 重进 dashboard → 新 ID。

## 3. 大脑侧实现

### 3.1 模块级缓存（带过期清理）

```python
# api/orchestrator.py（或新文件 api/session_cache.py）
from threading import Lock
from typing import Dict, Tuple
import time

# (session_id, domain) -> 已开新会话的时间戳（unix seconds）
_PART_SESSION_OPENED: Dict[Tuple[str, str], float] = {}
_PART_SESSION_TTL_SEC = 6 * 3600          # 6 小时无活动则视为过期
_PART_SESSION_LOCK = Lock()


def _mark_session_opened(session_id: str, domain: str) -> None:
    """记录 (session_id, domain) 已开新会话，用于下次复用判断。"""
    with _PART_SESSION_LOCK:
        _PART_SESSION_OPENED[(session_id, domain)] = time.time()


def _has_session_opened(session_id: str | None, domain: str) -> bool:
    """命中：(session_id, domain) 已开过新会话且未过期。"""
    if not session_id:
        return False
    with _PART_SESSION_LOCK:
        ts = _PART_SESSION_OPENED.get((session_id, domain))
        if ts is None:
            return False
        if time.time() - ts > _PART_SESSION_TTL_SEC:
            _PART_SESSION_OPENED.pop((session_id, domain), None)
            return False
        return True


def _gc_expired_sessions() -> int:
    """周期 GC 过期条目；可挂后台 asyncio task，每 30 分钟跑一次。"""
    now = time.time()
    expired = 0
    with _PART_SESSION_LOCK:
        keys = list(_PART_SESSION_OPENED.keys())
        for k in keys:
            if now - _PART_SESSION_OPENED[k] > _PART_SESSION_TTL_SEC:
                _PART_SESSION_OPENED.pop(k, None)
                expired += 1
    return expired
```

### 3.2 `_run_stage` 改造（核心）

定位：当前 `_run_stage(stage_name, task)` 处理单阶段（logaudit / pentest / intel / verdict / report）。新增 `session_id` 参数（或从 task payload 透出），在调用部件前判断是否需要 `/new`。

```python
async def _run_stage(stage_name: str, task: dict, session_id: str | None = None) -> None:
    domain = stage_name  # "logaudit" / "pentest" / "intel" / ...
    part = REGISTRY.get(domain)
    if not part:
        raise RuntimeError(f"part not registered: {domain}")

    # === 新增：会话复用判断 ===
    if session_id and _has_session_opened(session_id, domain):
        # 命中缓存 → 复用部件会话（不调 /new）
        log.info(f"[session] reuse {domain} session for {session_id}")
    else:
        # 未命中 OR 未传 session_id → 调 /new（清空上下文）
        try:
            await _part_post(part, "/new", timeout=10)
            if session_id:
                _mark_session_opened(session_id, domain)
                log.info(f"[session] new {domain} session opened for {session_id}")
        except Exception as e:
            log.warning(f"[session] /new failed for {domain}: {e}")
            # /new 失败不致命，继续往下走（部件可能已自带 session 隔离）

    # === 原 _run_stage 逻辑：调用部件 /submit 跑任务 ===
    submit_payload = {
        "input": task["task"],
        "target": task["target"],
        "params": task.get("params", {}),
    }
    # ... stream back ...
```

### 3.3 入口处透传 session_id

#### 3.3.1 `/api/tasks` POST handler

```python
@app.post("/api/tasks")
async def create_task(req: TaskRequest, background: BackgroundTasks):
    task = await db.create_task(req)
    # 把 session_id 一并存到 task 记录里（持久化也好、只传 background 也行）
    task["session_id"] = req.session_id

    background.add_task(_run_pipeline, task)
    return {"task_id": task["id"], "status": "pending", "domain": req.domain}


async def _run_pipeline(task: dict) -> None:
    session_id = task.get("session_id")
    for stage in pipeline_stages(task):
        await _run_stage(stage, task, session_id=session_id)
```

```python
@app.post("/api/chat/stream")
async def chat_stream(req: ChatRequest):
    session_id = req.session_id
    intent = await _assess_intent(req.message)

    if intent.is_task:
        task = await db.create_task_from_intent(intent, session_id=session_id)
        # ... 接力部件流（同 session_id 走缓存逻辑）...
        # 后续走 _run_stage(task, session_id=session_id) 复用上面 §3.2 逻辑
    else:
```

## 5. 风险与回滚

| 风险 | 概率 | 缓解 |
|---|---|---|
| `_PART_SESSION_OPENED` 内存膨胀（极端多 session_id） | 低 | TTL 6h 自动清理；后台 asyncio task 每 30min GC；进程重启清零 |
| `session_id` 客户端伪造导致跨用户复用部件会话 | **中** | 大脑侧需要鉴权 user → session_id 映射（鉴权已在 `/api/tasks` middleware 里），session_id 必须前缀当前 user_id（建议 linyuxuan 在 `_has_session_opened` 之前强制加 `f"{user_id}:{session_id}"` 命名空间） |
| `/new` 失败导致部件侧历史污染 | 低 | `/new` 失败不致命，只 log warning；后续可在部件侧再做防御 |
| 旧调用方（wails 桌面）`CreateTaskInput.session_id` 一直 undefined | 低 | 前端类型加 `?` 标记；老调用方不传 → 大脑退化到原行为 |
| 多个 dashboard mount 同 session_id | 极低 | session_id 含 Date.now()+rand8，重名概率 1/2^32 |

**回滚**：直接删 `_PART_SESSION_OPENED` + `_run_stage` 里的 if 分支 → 回到"每次任务都 /new"的原行为。**前端不受影响**（session_id 是可选字段，不传=被忽略）。
