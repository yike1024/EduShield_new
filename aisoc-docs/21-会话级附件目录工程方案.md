# 会话级附件目录工程方案（21 号）

**状态**：已评审（部署决策已确认）/ 待实施
**提出**：同事需求——用户上传的文件直接下载到服务器上"该会话"的目录
**前置**：19 号方案（save-attachment）已上线，但为全局附件池，未按用户/会话隔离
**已确认决策**：
- 附件根目录 → **共享存储**（NFS/对象存储，大脑与部件 8786/8788 共同挂载）
- 单文件上限 → **50MB**，超限 413
- 需要**下载 + 预览端点**（§3.6）

---

## 1. 需求与现状差距

| 维度 | 现状（19 号） | 目标（21 号） |
|---|---|---|
| 落盘路径 | `.reasonix/attachments/{safeName}` 全局池 | `{root}/{userId}/{conversationId}/{safeName}` |
| 隔离粒度 | 无（已报 bug：path 不含 userId） | 用户级 + 会话级双隔离 |
| 大文件 | 前端 200KB 内联截断（OpenSSH_2k 复现） | 全量落盘，大脑/部件按路径读盘 |
| LLM 上下文 | 文件全文塞进 prompt（爆上下文） | prompt 只带路径+摘要，内容由工具按需读 |
| 生命周期 | 无清理 | 会话删除时级联删目录 |

## 2. 目录设计

```
{ATTACHMENT_ROOT}/
  {userId}/
    {conversationId}/
      OpenSSH_2k.log
      取证镜像.pcap
    _pending/                # 会话尚未建立时的临时区
      {uploadId}_{safeName}
```

- `ATTACHMENT_ROOT` 默认 `.reasonix/attachments`，环境变量可配；**生产部署指向共享存储挂载点**（NFS 或对象存储 Fuse），大脑（6657）与部件（8786/8788）挂载同一路径，保证部件按路径可读
- 文件名沿用 19 号 safe-name 规则（去路径穿越、去控制字符）
- `_pending` 解决时序问题：用户在新会话（尚无 conversationId）先传文件

## 3. 后端改动（linyuxuan）

### 3.1 save-attachment 扩展

```
POST /api/save-attachment
{
  "name": "OpenSSH_2k.log",
  "dataUrl": "data:...;base64,...",
  "conversation_id": "uuid | null"        // 新增，可选
}
→ 200 {
  "path": "{userId}/{conversationId}/OpenSSH_2k.log",   // 相对 ATTACHMENT_ROOT
  "size": 265120,
  "conversation_bound": true
}
```

- 有 conversation_id：校验会话归属（非本人 → 404）→ 落会话目录
- 无 conversation_id：落 `_pending/`，返回 `upload_id`
- **单文件上限 50MB**（解码后字节数），超限 → 413 `{detail:"attachment exceeds 50MB limit"}`
- 鉴权修复（19 号已报 P0）：未带 Bearer 必须 401

### 3.2 pending 绑定（时序方案 A，推荐）

```
POST /api/attachments/bind
{ "upload_ids": ["..."], "conversation_id": "uuid" }
→ 200 { "bound": ["{userId}/{convId}/OpenSSH_2k.log"] }
```

- chat/stream 发出首条消息、收到 `conversation_bound` 帧后，前端调 bind 把 pending 文件 move 进会话目录
- 备选方案 B：前端先 `POST /api/conversations` 建空会话拿 id 再上传——改动更小但产生空会话垃圾，**不推荐**

### 3.3 chat/stream 协议扩展

```
POST /api/chat/stream
{
  "message": "审计这个日志",
  "conversation_id": "uuid",
  "attachments": [                         // 新增
    {"name": "OpenSSH_2k.log", "path": "{userId}/{convId}/OpenSSH_2k.log"}
  ],
  ...
}
```

- 大脑收到后：**prompt 只注入** `[附件] OpenSSH_2k.log → /abs/path/...（265 KB，可用 read_file / logaudit 工具读取）`
- **禁止**再把文件全文内联进 prompt（200KB 截断逻辑同步废弃）
- 日志审计/渗透部件的工具集需支持按路径读文件（logaudit 部件本身即从磁盘读日志，天然契合）

### 3.4 级联清理

- `DELETE /api/conversations/{id}` → 同步删除 `{userId}/{convId}/` 目录
- `_pending` 超过 24h 未 bind 的文件由定时任务清理

### 3.5 安全

- path 参数一律重新过 safe-name + 禁止 `..`，落盘前 `realpath` 校验必须落在该用户目录下
- 读文件的 API（§3.6）必须校验 path 的 userId 段 == 当前用户，否则 404

### 3.6 下载与预览端点（已确认需要）

```
GET /api/attachments/file?path={userId}/{conversationId}/{name}
  Authorization: Bearer <token>
  → 200  原始字节流，Content-Type 按扩展名推断，
         Content-Disposition: attachment; filename*=UTF-8''{name}
  → 404  路径不存在或不属于当前用户

GET /api/attachments/preview?path={...}&max_bytes=65536
  Authorization: Bearer <token>
  → 200 { "text": "前 N 字节 UTF-8 预览", "truncated": true,
          "size": 265120, "mime": "text/plain" }
  → 415  二进制不可预览（image/* 除外，image 直接走 file 端点 <img>）
  → 404  路径不存在或不属于当前用户
```

- preview 默认回前 64KB 文本（`max_bytes` 可调，上限 256KB），日志/文本类附件卡片内联展示用
- 二进制（pcap/镜像/压缩包）preview 返 415，前端卡片只提供下载按钮
- 两个端点共用同一段路径鉴权逻辑（userId 段校验 + realpath 防穿越）

## 5. 兼容与迁移

- 旧全局池文件保留只读，新上传一律走会话目录
- 200KB 以下小文件是否保留内联：**建议不保留**——统一路径心智负担小，且小文件落盘成本可忽略
- memoryCompiler / RAG 链路不受影响

## 6. 验收用例

```bash
# 1. 未授权 401
curl -X POST $B/save-attachment -d '{}' → 401

# 2. 新会话时序：先传（pending）→ 聊天建会话 → bind → 文件在会话目录
# 3. 已有会话直传：path 含 conversationId
# 4. OpenSSH_2k.log（260KB）全量落盘，size==原始大小
# 5. 他人 conversation_id → 404；path 穿透明 "..%2f" → 安全改写
# 6. 删除会话 → 目录消失
# 7. 大脑收到的 prompt 只含路径引用，不含日志全文（抓 SSE 上行验证）
# 8. 51MB 文件 → 413；恰好 50MB → 200
# 9. preview：文本附件 → 200 前 64KB + truncated 标志；pcap → 415
# 10. file：下载字节与原始一致（md5 比对）；他人 path → 404
# 11. 部件侧（8786/8788）按 path 在共享存储读到同一文件（跨机校验）
```
