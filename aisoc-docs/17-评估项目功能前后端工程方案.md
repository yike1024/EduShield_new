## 0. 一页纸结论

方案 B 的领域模型只有一句话：**一个项目 = 一次安全评估对象**（如"某中学官网 10.20.1.0/24"），会话 / 任务 / 发现都挂在项目下。

当前状态（2026-10-09 实测）：

- ✅ **前端已完成**：新建项目对话框、左栏项目树（项目文件夹 → 会话节点、未归类会话文件夹）、项目重命名/改色/置顶/删除/拖拽排序、项目下新建会话、项目 target 作为任务默认目标、`chat/stream` 请求带 `project_id`、SSE `conversation_bound` 帧解析 `projectId`。
- ✅ **前端已做静默降级**：后端没上线时，`GET /api/projects` 返回 404，前端自动切换到浏览器 localStorage 存储，功能完全可用；后端接口上线后前端自动切回服务端权威数据，并把本地项目**一次性迁移**到服务端。
- ❌ **后端缺口**：`/api/projects` 全部 404；`conversations` 表无 `project_id`；`chat/stream` 不识别 `project_id`（实测 pydantic 容忍未知字段，不报错但不生效）；任务/发现不按项目归集；聚合计数缺失。

**后端只需按本文档实现 P0（projects CRUD + conversations.project_id + chat 绑定），即可拿到完整闭环。**

## 1. 领域模型与归属规则

```
users (已存在)
  └─ projects（新增）               一个项目 = 一次安全评估
       ├─ conversations（已有表，加 project_id）
       │    └─ messages（已有，随会话间接归属）
       ├─ tasks（已有表，加 project_id，建议从会话继承）
       │    └─ findings（已有表，加 project_id，可从任务/会话继承）
       └─ （project_id = NULL 的会话/任务/发现 = 未归类，前端进"未归类会话"文件夹）
```

关键规则：

1. **项目强用户隔离**：所有项目按 token 解析的 `user_id` 隔离，禁止前端传 `user_id`。
2. **删除项目不级联删会话**：`DELETE /api/projects/{id}` 只删项目行，关联 `conversations.project_id` 置 `NULL`（会话回到"未归类"，历史不能丢）。
3. **销号级联**：`projects.user_id` 外键 `ON DELETE CASCADE`（用户删账号则项目一并删除，会话本身按 users 现有级联策略处理）。
4. **会话绑定时机**：`chat/stream` 建会话时若请求带 `project_id` 则写入；已绑定会话后续轮次忽略请求体里的项目变更（改归属走 `PUT /api/conversations/{id}`）。
5. **任务/发现归属**：后端从会话的 `project_id` 继承写入，不需要前端额外传。

## 3. 通用约定

与 16 号方案完全一致，后端可复用同一套依赖与序列化器：

1. **鉴权**：除 `/api/auth/*` 外全部 Bearer Token；`user_id` 一律从 token 解析，**请求体/query 中的 user_id 一律忽略**。
2. **响应命名**：JSON 响应字段 **camelCase**（`createdAt`、`conversationCount`…），与现有 `/api/conversations`、`/api/memory` 保持一致。
3. **请求命名**：请求体/query 沿用 **snake_case**（`page_size`、`project_id`、`use_memory`），与 `chat/stream` 现有风格一致。
4. **时间**：ISO-8601 UTC 字符串（`2026-10-09T10:00:00Z`），与 conversations 实测一致。
5. **分页响应**：
   ```json
   { "items": [ ... ], "total": 0, "page": 1, "pageSize": 200 }
   ```
6. **错误响应**：沿用现有形态 `{"error": "...", "detail": "..."}`，状态码：
   - `401` 未认证/token 失效；
   - `404` 资源不存在或**不属于当前用户**（不区分"不存在"与"无权限"，防资源探测）；
   - `422` 字段校验失败（如 name 为空、color 不在白名单）；
   - `405` 方法不允许（前端同样视为降级信号）。
7. **DELETE 必须返回 JSON 体**（如 `{"ok": true}`），不要返回空 204——前端 HTTP 封装对所有响应统一 `response.json()`，空响应会导致前端拿到解析异常。

## 4. 数据库变更（PostgreSQL）

### 4.1 新建 `projects` 表

```sql
CREATE TABLE projects (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id     UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    name        TEXT NOT NULL,
    target      TEXT NULL,                 -- 评估目标：IP/CIDR/域名/URL
    description TEXT NULL,
    color       VARCHAR(16) NULL,          -- 颜色 key 白名单，NULL/''=默认
    pinned      BOOLEAN NOT NULL DEFAULT FALSE,
    sort_order  DOUBLE PRECISION NULL,     -- 注意：order 是 SQL 保留字，列名用 sort_order；API 字段仍叫 order
    status      VARCHAR(16) NOT NULL DEFAULT 'active',  -- active | archived
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 用户内列表查询：默认按 active 过滤 + 更新时间排序
CREATE INDEX idx_projects_user_status ON projects (user_id, status, updated_at DESC);
-- 置顶/手动排序查询
CREATE INDEX idx_projects_user_sort   ON projects (user_id, pinned DESC, sort_order ASC)
    WHERE status = 'active';
```

字段约束建议（应用层或数据库 check 均可）：

- `name`：去空白后长度 1–40，`''` 拒绝（422）；
- `target`：长度 ≤ 200，不做强制格式校验（IP/CIDR/域名/URL 形态多样，由任务侧校验）；
- `color`：`NULL | '' | red|orange|amber|green|teal|blue|purple|pink`，非法值 422；
- `status`：`active | archived`。

### 4.2 `conversations` 表加列

```sql
ALTER TABLE conversations
    ADD COLUMN project_id UUID NULL REFERENCES projects(id) ON DELETE SET NULL;

CREATE INDEX idx_conversations_project ON conversations (project_id, updated_at DESC);
-- 未归类列表（project_id IS NULL）的过滤索引，可选
CREATE INDEX idx_conversations_user_noproj ON conversations (user_id, updated_at DESC)
    WHERE project_id IS NULL;
```

`ON DELETE SET NULL` 与 §1 规则 2 对应：删项目不解绑/不删会话。

### 4.3 `tasks`、`findings` 表加列（P1，可与项目表同版本做）

```sql
ALTER TABLE tasks
    ADD COLUMN project_id UUID NULL REFERENCES projects(id) ON DELETE SET NULL;
ALTER TABLE findings
    ADD COLUMN project_id UUID NULL REFERENCES projects(id) ON DELETE SET NULL;

CREATE INDEX idx_tasks_project    ON tasks (project_id, created_at DESC);
CREATE INDEX idx_findings_project ON findings (project_id, severity, created_at DESC);
```

写入规则：任务创建时，若其会话有 `project_id` 则继承；部件回传 finding 时沿 task → conversation 链路继承。

### 4.4 `updated_at` 维护

建议触发器或 ORM 钩子在 UPDATE 时刷新 `updated_at = now()`，左栏排序依赖它。

## 5. 接口清单

### 5.1 列出项目 `GET /api/projects`

Query（全部可选）：

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `page` | int | 1 | 页码 |
| `page_size` | int | 20（前端固定传 200） | 每页条数 |
| `q` | string | — | 模糊搜索 `name` / `target` / `description` |
| `status` | `active`\|`archived` | 不传=全部 | 前端建树时显式传 `status=active` |

排序：`pinned DESC, sort_order ASC NULLS LAST, updated_at DESC`。

**建议**：列表项带聚合计数（子查询计数，按当前用户+项目过滤）：
`conversationCount`（status 正常的会话数）、`taskCount`、`findingCount`。这三个字段前端缺省时不显示徽标，因此**首版可以先不返回**，后续补字段无需版本升级。

响应 `200`：

```json
{
  "items": [
    {
      "id": "7e2c…", "name": "某中学官网安全评估",
      "target": "10.20.1.0/24", "description": "等保整改前自查",
      "color": "blue", "pinned": false, "order": 0, "status": "active",
      "createdAt": "2026-10-09T10:00:00Z", "updatedAt": "2026-10-09T10:05:00Z",
      "conversationCount": 3, "taskCount": 2, "findingCount": 11
    }
  ],
  "total": 1, "page": 1, "pageSize": 200
}
```

### 5.2 创建项目 `POST /api/projects`

请求体：

```json
{ "name": "某中学官网安全评估", "target": "10.20.1.0/24", "description": "可选", "color": "blue" }
```

- `name` 必填（trim 后非空，否则 422）；其余可选；
- 服务端补默认值：`pinned=false`、`status='active'`、`sort_order` 取该用户当前 active 项目数（或 NULL，前端均可处理）、时间戳。

响应 `201`：返回完整 `ProjectDto`（同 §5.1 单项结构，计数字段此时可给 0 或省略）。

### 5.3 项目详情 `GET /api/projects/{id}`

- 属于当前用户 → `200` 完整 `ProjectDto`；
- 不存在/不属于该用户 → `404`（统一文案，不区分）。

### 5.4 更新项目 `PATCH /api/projects/{id}`

字段级更新，请求体只包含要改的字段：

```json
{ "name": "新名称", "target": null, "color": "red", "pinned": true, "order": 2, "status": "archived" }
```

语义约定（前端依赖）：

- `target` / `description` / `color` 显式传 `null` 表示**清空**（与不传"不变"区分）；
- `color: null` 或 `""` 都表示恢复默认色；
- `order` 接受数字（拖拽排序时前端对一批项目依次 PATCH，值为 0..n 排名）；
- name trim 后为空 → 422；资源不属于该用户 → 404。

响应 `200`：更新后的完整 `ProjectDto`。

> 说明：前端拖拽排序会并发多个 PATCH（不同 id），后端需保证各自独立更新、无跨行锁竞争问题（不同行 UPDATE 天然满足）。

### 5.5 删除项目 `DELETE /api/projects/{id}`

- 服务端动作：`conversations.project_id`、`tasks.project_id`、`findings.project_id` 全部置 `NULL`（外键 `ON DELETE SET NULL` 自动完成），再删项目行；
- **不删除**会话/消息/任务/发现；
- 响应 `200`，**JSON 体**（不可空 204）：

```json
{ "ok": true, "id": "7e2c…", "unboundConversations": 3 }
```

- 不存在/不属于该用户 → `404`。

### 5.6 会话列表增加项目过滤 `GET /api/conversations`

在现有接口（已实测可用）基础上增加 query：

| 参数 | 类型 | 说明 |
|---|---|---|
| `project_id` | UUID 字符串 | 只返回该项目下会话 |
| `project_id=none` | 字面量 `none` | 只返回**未归类**会话（`project_id IS NULL`） |
| 不传 | — | 全部（前端建树时不传，一次性拉全量在前端分组） |

响应 items 每项**增加 `projectId` 字段**（UUID 或 `null`），其余字段（id/title/domain/pinned/status/summary/messageCount/tokenCount/createdAt/updatedAt）保持现状：

```json
{
  "items": [
    { "id": "…", "title": "外网打点记录", "projectId": "7e2c…", "pinned": false,
      "status": "active", "domain": null, "summary": null,
      "messageCount": 4, "tokenCount": 9120,
      "createdAt": "…", "updatedAt": "…" }
  ],
  "total": 1, "page": 1, "pageSize": 200
}
```

无效 UUID（非 `none` 且格式非法）→ 422；传了不存在/不属于该用户的项目 id → 返回 `{"items":[],"total":0,…}` 即可（或 404，二选一，建议空列表，前端均能处理）。

### 5.7 更新会话归属 `PUT /api/conversations/{id}`

现有 PUT（重命名/置顶）请求体增加可选字段：

```json
{ "title": "新标题", "pinned": true, "project_id": "7e2c…" }
```

- `project_id` 传 UUID：绑定/移动到该项目（必须是当前用户自己的项目，否则 422/404）；
- 显式传 `null`：移回未归类；
- 不传：不变；
- 响应 `200`：更新后的会话摘要 JSON（结构同列表项）。前端未来的"把会话移动到其他项目"功能依赖此接口（当前 UI 未开放移动入口，但接口可先行）。

### 5.8 对话接口接收 `project_id`

`POST /api/chat/stream`（以及保持对称的 `POST /api/chat`）请求体增加：

```json
{
  "message": "对 10.20.1.5 做端口扫描",
  "conversation_id": "…",
  "use_memory": true,
  "pass_through": true,
  "project_id": "7e2c…"
}
```

后端行为：

1. `project_id` 必须属于当前用户，否则忽略（建议当作 422；但**不得 500**）。降级期前端会传本地 `local-xxx` id 吗？**不会**——local 模式下前端不发 `project_id`（local 模式只走 LS，且无 token 不调流式落库链路）；迁移后旧 tab 的 id 经别名解析成服务端 UUID 才发送。尽管如此，后端对无法识别的 project_id 建议宽容忽略（置 NULL），避免任何历史 tab 导致 422 阻断对话。
2. **建会话时**：无 `conversation_id` 且带了合法 `project_id` → 新建 conversations 行写入该 project_id。
3. **续接会话时**：以会话现有 project_id 为准，请求体中的 project_id 不做覆盖。
4. 创建任务时把 `project_id` 继承写入 tasks；部件回传 finding 时沿 task 继承到 findings。
5. pydantic 模型直接加字段即可（`project_id: UUID | None = None`），实测当前多余字段被容忍不会 422。

### 5.9 SSE 帧：`conversation_bound` 增加 `projectId`

首条 delta 之前的绑定帧改为：

```json
{"kind": "conversation", "id": "会话UUID"}
{"kind": "conversation_bound", "conversationId": "会话UUID", "projectId": "项目UUID或null", "task_id": "T-…"}
```

- 前端已兼容 `projectId` 缺省（旧后端不下发也不报错）；
- 未归类会话该字段可省略或给 `null`。

### 5.10 任务/发现的项目过滤与计数（P1）

- 建议 `GET /api/tasks?project_id=<uuid>`、`GET /api/findings?project_id=<uuid>` 支持过滤（含 `none`），风格同 §5.6；
- §5.1 的 `taskCount` / `findingCount` 从这两张表计数；
- 前端当前左栏只聚合会话，任务/发现的项目视图是后续迭代，**不阻塞 P0**。

## 6. 端到端时序（后端实现对照）

```
浏览器                                大脑 :6657                           PostgreSQL
──────                                ────────────                         ──────────
打开左栏
GET /api/projects?status=active ─────▶ 鉴权 user_id ─▶ SELECT … ───────────▶ projects
◀──── {items:[…]}（未部署时 404 → 前端 LS 降级，用户无感）
GET /api/conversations?page_size=200 ▶ SELECT … project_id ───────────────▶ conversations
（前端按 projectId 把会话挂进对应项目文件夹，NULL 的进"未归类会话"）

新建项目
POST /api/projects {name,target,…} ───▶ INSERT projects ──────────────────▶ 
◀──── 201 ProjectDto
（前端随即 SwitchWorkspace + 开空白会话 tab，不调后端）

项目下首轮提问
POST /api/chat/stream {message, project_id}
                                    ─▶ INSERT conversations(project_id) ─▶ conversations
                                    ─▶ SSE conversation / conversation_bound{projectId}
                                    ─▶ INSERT tasks(project_id 继承) ─────▶ tasks
                                    ─▶ findings 继承 project_id ─────────▶ findings
SSE ◀──── delta … turn_done

右键重命名/改色/置顶/排序
PATCH /api/projects/{id} ────────────▶ UPDATE projects
右键删除（两步确认）
DELETE /api/projects/{id} ───────────▶ SET NULL 关联 ─▶ DELETE row ──────▶ 
◀──── 200 {"ok": true}
（前端同时关闭该项目下所有本地 tab，不需要额外接口）
```

## 7. 验收用例（curl）

```bash
TOK=<登录 token>
BASE=http://localhost:6657/api   # 经 :3000 反代时用 http://localhost:3000/api

# 1) 建项目
curl -s -XPOST "$BASE/projects" -H "Authorization: Bearer $TOK" -H 'Content-Type: application/json' \
  -d '{"name":"验收中学官网","target":"10.20.1.0/24","color":"blue"}'
# 期望 201 + 完整 ProjectDto，记下 id=PID

# 2) 列表
curl -s "$BASE/projects?status=active&page_size=200" -H "Authorization: Bearer $TOK"
# 期望 items 含该项目，分页四字段齐全

# 3) 改名/置顶/排序
curl -s -XPATCH "$BASE/projects/$PID" -H "Authorization: Bearer $TOK" -H 'Content-Type: application/json' \
  -d '{"name":"验收项目改名","pinned":true,"order":0}'
# 4) 清空目标
curl -s -XPATCH "$BASE/projects/$PID" -H "Authorization: Bearer $TOK" -H 'Content-Type: application/json' \
  -d '{"target":null}'
# 5) 校验：空名称 422
curl -s -o /dev/null -w '%{http_code}\n' -XPOST "$BASE/projects" -H "Authorization: Bearer $TOK" \
  -H 'Content-Type: application/json' -d '{"name":"  "}'   # 期望 422

# 6) 项目下对话（如脑服务可用）
curl -s -N -XPOST "$BASE/chat/stream" -H "Authorization: Bearer $TOK" -H 'Content-Type: application/json' \
  -d '{"message":"你好","pass_through":true,"project_id":"PID"}'
# 期望首条 delta 前出现 conversation_bound 且带 projectId=PID

# 7) 会话列表带 projectId
curl -s "$BASE/conversations?page_size=5" -H "Authorization: Bearer $TOK"
# 期望新建会话 projectId=PID

# 8) 未归类过滤
curl -s "$BASE/conversations?project_id=none" -H "Authorization: Bearer $TOK"
# 期望只含 projectId=null 的会话

# 9) 删除（解绑不级联）
curl -s -XDELETE "$BASE/projects/$PID" -H "Authorization: Bearer $TOK"
# 期望 200 JSON {"ok":true…}；随后 #7 的会话仍在，projectId 变 null
# 再查详情期望 404
```

多租户补充验收：用 B 用户 token 访问 A 用户的 `GET/PATCH/DELETE /projects/{A的id}` 必须全部 404。

## 8. 上线注意事项（前端兼容性）

1. **零停机兼容**：接口未上线时前端走 LS 降级；接口上线瞬间前端自动切换，旧 bundle 不会因为新字段报错（未知响应字段一律忽略）。
2. **不要提前占用状态码语义**：`/api/projects` 在未部署版本必须保持 404/405；若部署了网关但路由缺失返回 500，前端虽也降级但会打 warning。
3. **一次性迁移触发条件**（前端逻辑，后端无需配合，仅供理解数据现象）：
   - 该浏览器从未迁移过（LS 无迁移标记）；
   - `GET /api/projects` 返回 `items` 为空；
   - 本地 LS 中有降级期创建的项目。
   - 满足时前端会逐个 POST 补建，所以后端上线后**最初几分钟可能看到一批 name 为用户测试项目的 INSERT**，属预期；迁移完成后别名落盘，后续不再重复。
4. **响应必须始终 JSON**（含 DELETE），时间统一带时区的 ISO-8601。
5. 颜色、状态枚举以后端白名单为准；前端只从固定色板取值，新增颜色需前后端同步色板（`src/lib/projectColors.ts`）。
