# 多账号本地缓存隔离前后端工程方案（userId 命名空间版）

> 版本 v1.0 · 2026-10-12 · 状态：待实施
> 前置：17 号方案（评估项目）、16 号方案（记忆）、2026-10-12 换账号缓存泄漏热修（logout 清缓存 + cache-owner 检测）

---

## 1. 一页纸结论

- **问题**：浏览器本地会话/项目缓存是全局键，换账号只能"切换即清空"，A→B→A 后 A 的本地数据全丢；且依赖 logout/登录检测两处兜底清理，漏径多（过期、多端）。
- **方案**：把 9 个用户域 localStorage 键改造为 **userId 命名空间键**（`reasonix:web:{name}:{userId}`），各账号数据天然共存、互不污染；换账号从"清缓存 + reload"退化为"仅 reload"。
- **后端：零必改**。服务端数据本就按 userId 隔离，本方案纯前端；后端仅需确认两项既有契约稳定（§6）。
- **工作量**：前端约 **2 人日**（含测试），后端 0.5 人日（文档与契约确认）。
- **顺带落实**两项热修遗留改进：logout 吊销可靠性（sendBeacon）、401 防抖（§5.3、§5.4）。

## 2. 现状盘点

### 2.1 键清单与读写点

| 键（现状全局） | 归属模块 | 读取点 | 写入点 | 内容 |
|---|---|---|---|---|
| `reasonix:web:histories` | webApiProxy | restoreFromStorage | saveToStorage | tabId → 消息数组 |
| `reasonix:web:tabs` | webApiProxy | restoreFromStorage | saveToStorage | TabMeta[] |
| `reasonix:web:tab:active` | webApiProxy | restoreFromStorage | saveToStorage | 活动 tabId |
| `reasonix:web:memory` | webApiProxy | restoreFromStorage | saveToStorage ×2 | 手动记忆兜底（服务端 /api/memory 优先） |
| `reasonix:web:conversations` | webApiProxy | restoreFromStorage | saveToStorage | tabId → conversation_id |
| `reasonix:web:projects:v1` | webProjects | 构造器 | snapshot | 项目列表（local 降级数据） |
| `reasonix:web:projects:active` | webProjects | 构造器 | ×2 | 当前项目 id |
| `reasonix:web:projects:migrated` | webProjects | migrateLocalOnce | ×1 | local→server 一次性迁移标记 |
| `reasonix:web:projects:aliases` | webProjects | 构造器 | ×1 | localId→serverId 别名 |

**设备级键（不命名空间化，保持全局）**：`reasonix:web:theme`、`reasonix:web:theme-style`、`reasonix:web:deepseek_api_key`、`reasonix:web:deepseek_model`、`reasonix:perf-reported`。

**认证键（保持全局）**：`edushield:session`（localStorage/sessionStorage）、`edushield:cache-owner`。

### 2.2 热修后行为（本方案的基线）

- `logout()`：清 9 键 + cache-owner + session → reload。
- `login()`：cache-owner 与新 userId 不一致 → 清 9 键 → reload。
- 缺陷：① 切回旧账号本地数据已丢；② 清理列表硬编码在 auth.ts，新增键易漏；③ 共享电脑上"销毁式隔离"与"保留各自数据"不可兼得。

## 3. 目标语义

1. 每个账号的本地缓存独立读写，键形如 `reasonix:web:histories:u84bd8cad-…`。
2. 换账号：**不丢任何一方的本地数据**，仅 reload 重挂载。
3. 未登录（匿名）态使用 `anon` 命名空间；**首次登录时**若 anon 有数据且目标用户命名空间为空，则一次性并入该用户（保持"未登录先用、登录后数据还在"的现有体验）。
4. logout 不再销毁数据；提供显式"清除本账号本地缓存"入口（设置页，P1）。
5. 旧全局键自动迁移，用户无感知。

## 4. 前端改动（主体，约 2 人日）

### 4.1 新增 `src/lib/userScopedStorage.ts`（约 80 行）

唯一键解析器，所有用户域读写收口：

```ts
// 解析当前命名空间：已登录 → userId；未登录 → 'anon'
export function currentNs(): string;           // 读 authApi.getCurrentSession()?.userId ?? 'anon'
export function nsKey(base: string): string;   // `${base}:${currentNs()}`
export function readNs<T>(base: string, fallback: T): T;
export function writeNs(base: string, value: unknown): void;
export function removeNs(base: string): void;
export function migrateLegacyKeys(): void;     // §4.4 旧全局键 → 当前命名空间
export function adoptAnonIfFirstLogin(userId: string): void; // §4.5 anon 并入
```

依赖方向：`userScopedStorage → lib/auth`（auth 不反向依赖，无环）。**9 个键的 base 名常量化在此文件**，作为唯一事实源，消灭 auth.ts 里的硬编码列表。

### 4.2 webApiProxy 改造（5 个键 × 各 2-3 处）

- `LS_KEY_*` 常量由字面值改为 base 名；`restoreFromStorage()` / `saveToStorage()` / 两处 memory 直写 / conversations 直写，全部改走 `readNs/writeNs`。
- 构造器首行调用 `migrateLegacyKeys()`，再按命名空间恢复。
- 主题、API key 相关读写保持原全局键不动。

### 4.3 webProjects 改造（4 个键）

- `readLSJson/writeLSJson` 调用点换 `readNs/writeNs`；`migrateLocalOnce` 的 migrated 标记自然变成 per-user（每个账号各自做一次 local→server 迁移，语义正确：不同账号的 local 项目本就该分别迁移到各自服务端空间）。

### 4.4 旧版迁移（upgrade path）

`migrateLegacyKeys()`：全局标记 `reasonix:web:ns-migrated` 未置位时——
1. 若旧全局键（无后缀的 9 键）存在，搬入**当前**命名空间（已登录→该用户，未登录→anon）；
2. 删除旧全局键，置位标记。
热修版用户升级后：缓存已在热修 logout 时被清，此步骤基本空转；更老版本用户的数据可保全。

### 4.5 登录/登出语义简化（auth.ts + store/auth.ts）

- `login()`：保留 cache-owner 比对；`switchedAccount=true` 时**只做两件事**：`adoptAnonIfFirstLogin(user.id)` + reload（由 store 层执行）。**删除** `clearUserScopedLocalCache()` 调用。
- `logout()`：**删除**清缓存与 cache-owner 移除，只保留清 session + 吊销 + reload。cache-owner 在下次 login 时自然被覆盖。
- `adoptAnonIfFirstLogin`：anon 命名空间 9 键中任一存在、且 `*:{userId}` 全部不存在时，整体搬运；否则不动（防共享电脑上 anon 数据被后来者吞并已有账号数据）。

### 4.6 设置页手动清理入口（P1，可后置）

设置 → 数据："清除本账号在本机的缓存数据"按钮 → 删当前命名空间 9 键 + reload。共享电脑敏感场景的逃生门。

### 4.7 测试

- 新增 `src/__tests__/user-scoped-storage.test.ts`（沿用 tsx 脚本式单测）：
  - 命名空间隔离：A 写 9 键 → 切 B → 读到空；切回 A → 数据原样在；
  - anon → 登录并入：anon 写数据 → login(A) → A 命名空间获得数据、anon 清空；
  - anon 不覆盖已有账号：A 命名空间已有数据时 anon 不并入；
  - 旧全局键迁移：置旧键 → 构造 → 数据进当前命名空间、旧键删除、标记置位；
  - logout 后 A 数据保留、session 清除。
- 更新 `web-projects.test.ts` 中 LS 键断言为命名空间形态。
- 浏览器端到端沿用本次冒烟剧本，追加"A→B→A 切回后本地会话仍在"。
- **测试链位置**：插在 `composer-goal-toggle` 之前（该用例预存失败会中断 && 链）。

## 5. 顺带落实的热修遗留项

### 5.3 logout 吊销可靠性（前端，0.2 人日）

现状：`logout()` 里 `fetch POST /api/auth/logout` 未 await，紧随的 reload 将其中断（实测 ERR_ABORTED），后端可能收不到吊销。
改法：改用 `navigator.sendBeacon(url, '{}')`（页面卸载也保证送达），无 sendBeacon 时回退 `fetch(..., { keepalive: true })`。无需 await，reload 照旧。

### 5.4 401 防抖（前端，0.3 人日）

现状：任一 `/api/*` 401 立即 logout + reload，网络抖动/后端重启窗口期会把用户闪退到登录页。
改法（`aisoc-api.ts` 广播点）：首次 401 后 3s 内不发 `edushield:unauthorized`，而是带原 token 重试一次 `GET /api/auth/me`（见 §6.2）；仅当 /me 也 401 时才广播登出。重试期间后续 401 合并静默。

## 6. 后端配合（零必改，仅契约确认 + 1 个可选接口）

### 6.1 确认项（无需开发，回归验证即可）

| 契约 | 用途 | 现状 |
|---|---|---|
| `POST /api/auth/login`、`/register` 响应含 `user.id` 且全局唯一稳定 | 命名空间 key 的 userId 来源 | ✅ 已具备，前端已消费 |
| 会话/项目/记忆/任务接口按 Bearer 用户隔离 | 服务端数据层与本地命名空间语义一致 | ✅ 已验证（A 建对话 B token 查询为空） |

### 6.2 建议新增：`GET /api/auth/me`（P1，0.3 人日）

- 请求：`Authorization: Bearer <token>`；响应 200 `{ user: { id, username, email, createdAt } }`，401 表示 token 无效/被吊销。
- 用途：① §5.4 的 401 防抖确认；② 前端启动时校验本地 session 是否仍被服务端承认（当前只查本地过期时间，token 被吊销后直到首个 401 才被发现）。
- 若后端暂不上线，§5.4 退化为"3s 内连续 2 次业务 401 才登出"，不阻塞。

### 6.3 文档同步

`docs/frontend-api.md`：§认证 补充 /logout 幂等说明（重复调用返回 200）、401 语义（token 无效/过期/吊销三类不分）、（如上线）§8.x 增加 /me 契约。前端命名空间行为在本文档自包含，不需要后端文档描述。

## 7. 时序图（换账号，方案落地后）

```
A 已登录，本地键均为 *:uA
用户点退出 → logout(): 吊销(sendBeacon) → 清 session → reload
  ↓ （*:uA 数据原样保留在 localStorage）
登录页输 B → login(): cache-owner(uA)≠uB
            → adoptAnonIfFirstLogin(uB)（通常空转）
            → 写 cache-owner=uB → reload
  ↓ webApiProxy/webProjects 构造：读 *:uB（空）+ GET /api/conversations（B 的服务端会话）
B 看到干净视图；A 的 *:uA 数据分毫未动
B 退出 → 登录 A → reload → 读 *:uA → A 的本地会话/项目完整恢复
```

## 8. 风险与取舍

| 项 | 说明 | 对策 |
|---|---|---|
| 共享电脑数据驻留 |  logout 不再清数据，同机他人登录自己账号看不到别人数据（命名空间隔离），但**本地取证可见** | §4.6 手动清理入口；涉密场景建议后端加"账号级禁止本地缓存"标记（远期，不在本期） |
| anon 并入的归属歧义 | 共享电脑上 anon 数据会并入下一个登录者 | §4.5 仅在目标用户无数据时并入；仍有歧义但概率低，文档明示 |
| localStorage 容量 | 多账号数据共存累积 | 现状数据量小（消息/项目元数据），远期可加 LRU 清理，不在本期 |
| reload 体验 | 仍有一次整页刷新 | 换账号是低频重操作，可接受；彻底消灭需单例可重建，改动大，不做 |
