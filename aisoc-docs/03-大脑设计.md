## 1. 模块划分

```
FastAPI (6657)
├── api/            路由层：/api/tasks /api/verdict /api/knowledge /api/reports ...
├── orchestrator/   编排调度（核心）
├── verdict/        威胁判定引擎
├── knowledge/      ChromaDB 知识库封装
├── session/        会话管理（状态机/队列/审批流）
├── eventhub/       实时事件聚合（订阅各部件 SSE → /api/stream 推给前端）
├── audit/          思维链账本落库
├── report/         报告生成
├── registry/       部件注册表
└── static/         前端面板（复用 EduShield static/index.html，扩展实时面板）
```

**铁律**：AI 只加在判断/生成处（编排决策、判定、报告、路由），流程/状态/存储必须纯业务代码（确定性逻辑）。

## 2. 编排调度（orchestrator）

### 2.1 职责

- 接收任务 → 白名单校验（target ∈ 授权名单）→ 分解 → 下发到部件 → 回收证据 → 汇总判定
- 多阶段管道：侦察 → 扫描 → 审计 → 处置（按任务类型编排阶段顺序/依赖/并行）

### 2.2 管道定义（P1 至少支持）

| 管道 | 阶段序列 | 说明 |
|---|---|---|
| 数据泄露调查 | logaudit → pentest → verdict → report | 旗舰场景 |
| 攻击链调查 | logaudit → pentest → verdict → report | 先审计定位再渗透验证 |
| 上线评估 | pentest ∥ logaudit → 合规 → verdict → report | 并行阶段 |
| 攻防演练 | pentest ∥ logaudit → 实时态势 → report | 红蓝并行 |

### 2.3 编排状态机（纯业务）

```
pending → running → (approval) → completed
              │          │
              ├─ failed ─┴─ cancelled
              └─ archived（≥180 天）
```

- 每阶段有超时（默认 `params.timeout_s`）、重试（≤3 次指数退避）、降级（部件失败走备选/人工）
- 部分失败策略：关键阶段失败 → 任务置 `failed`；非关键阶段失败 → 标记降级继续

### 2.4 防误报传播

- 部件 A 的 Finding 进入大脑后先过"交叉验证"：与其他部件证据/知识库对照
- 多源印证一致 → 置信度上调；矛盾 → 下调并标记 `pending_review`
- 阶段间传递的是**证据摘要**而非原样结论，防止错误在链条上放大

## 3. 威胁判定（verdict）

### 3.1 双轨判定（ADR-6）

```
输入：任务 + 全部 Finding
  ├─ 规则轨：误报抑制规则（爬虫≠攻击、选课高并发≠DDoS、端口扫描≠入侵…）+ 阈值判断
  └─ LLM 轨：EduShield verdict/confidence 模型（移植为 Go/Python 调用）
合并：verdict + confidence + 判定理由（每次判定必须可复核）
```

### 3.2 输出结构

```json
{
  "verdict": "real_threat | false_positive | pending_review",
  "confidence": 0.0-1.0,
  "threats": [{"type": "brute_force", "severity": "high", "mitre": ["T1110"]}],
  "reason": "判定理由（可复核）",
  "rules_fired": ["rule:爬虫排除", "rule:端口扫描-低危"]
}
```

### 3.3 校准要求（联调阶段）

- 建立靶场回归基线：误报率 ≤ 20%、关键威胁漏报率 = 0
- 每次判定记录 verdict/confidence 与人工复核结果，用于持续校准阈值

## 4. 安全知识库（knowledge）

- 复用 EduShield ChromaDB（`chroma_data/`，33 条资产起步）：OWASP Top 10 / ATT&CK / CVE / 等保 2.0 / 校园误报
- 查询接口：`GET /api/knowledge/search?q=&k=`；播种 `POST /api/knowledge/seed`
- 编排决策前自动检索注入（Planner 决策依据）；判定时用于交叉验证

---

## 5. 会话管理（session，纯业务）

### 5.1 职责边界

| 职责 | 实现 |
|---|---|
| 生命周期状态机 | 确定性代码（见 2.3） |
| 任务队列/并发/限流/多用户隔离 | 纯业务 |
| 审批流（复用 reasonix Approver 语义） | 纯业务流转 |
| 会话存储/恢复（SQLite + checkpoint） | 纯业务 |
| AI 增强（二期）：摘要/意图路由/风险提示 | 轻量 LLM 可选 |

### 5.2 数据模型（SQLite 初版）

```sql
tasks(id TEXT PK, task_id TEXT UNIQUE, domain TEXT, target TEXT,
      status TEXT, verdict TEXT, confidence REAL, created_at, updated_at);
findings(id TEXT PK, task_id TEXT REFERENCES tasks, domain TEXT, target TEXT,
         tool TEXT, severity TEXT, cve TEXT, cwe TEXT, cvss REAL,
         title TEXT, description TEXT, evidence TEXT, remediation TEXT,
         confidence REAL, mitre TEXT, ts TEXT);
ledger(id INTEGER PK, task_id TEXT, ts TEXT, actor TEXT, action TEXT,
       detail TEXT);   -- 思维链账本：谁/何时/做了什么/为什么
reports(id TEXT PK, task_id TEXT, domain TEXT, content TEXT, created_at);
```

### 5.3 审批流

- 写入类操作（封禁/利用/配置修改）：状态进入 `approval`，等待人工确认
- 审批超时默认 5 分钟 → 拒绝；审批人/审批记录写入 ledger
- 前端面板（复用 EduShield UI）提供审批入口

---

## 6. 审计留档（audit）

- 思维链账本：每一步（prompt → 工具调用 → 证据 → 判断理由）结构化写入 `ledger` 表
- **留档 ≥ 180 天**，可导出（JSON/Markdown）
- 导出内容含：任务元数据、全部 Finding、判定理由、审批记录、报告快照
- 审计日志只增不删；删除任务走"归档"而非物理删除

---

## 7. 报告生成（report）

- 按部件出专业报告：渗透报告 / 审计报告 / 等保合规检查
- 报告引用 Finding id（可追溯）+ 附录思维链
- 跨域综合报告（domain=all）：多部件发现拼成一份，标注证据来源

---

## 8. 部件注册表（registry）

```json
{
  "pentest":    {"host": "127.0.0.1", "port": 8787, "token": "tk_pentest_xxx", "auth": "token"},
  "logaudit":   {"host": "127.0.0.1", "port": 8788, "token": "tk_logaudit_xxx", "auth": "token"}
}
```

- 大脑启动时加载；**新增部件 = 注册表加一行**
- 下发任务时从注册表取 host/port/token，按 `domain` 路由
- token 由大脑生成并下发，部件 serve 以 `--auth token` 启动（见 05）

## 10. 实时事件面板（EventHub + /api/stream）

> 需求：前端实时显示"哪个 agent 在做哪个事 + 流式输出结果"。
> 数据基础：reasonix `/events` 事件流原生含 `Source`（executor/planner/subagent）、`Tool{Name, Partial, Output}`、`Phase`、`Text/Reasoning`（`event.go`），无需改 reasonix 代码。

### 10.1 架构

```
各部件 /events (SSE) ──▶ 大脑 EventHub ──▶ 前端 GET /api/stream (SSE)
  pentest:8787 ─┐      聚合 + 标注 task_id/domain
  logaudit:8788 ─┴─▶  {task_id, domain, event} ──▶ Agent 状态墙 + 流式输出区
```

- **EventHub**：常驻订阅每个部件一条 SSE；将实例内事件**补上 `task_id`/`domain` 标注**（事件本身只有实例内信息，按大脑会话上下文映射）；按前端订阅分发
- **`GET /api/stream`**：SSE 端点，前端一条连接收全平台实时事件（`text/event-stream`，15s keepalive）
- **订阅粒度**：前端可选 `?task_id=` 过滤单任务，或 `?domain=` 过滤单部件，缺省=全平台

### 10.2 事件 → 前端展示映射

| reasonix 事件 | 面板动作 |
|---|---|
| `TurnStarted` | 对应 agent 卡片亮起（进入工作态） |
| `Phase`（如 planner→executor 交接） | 阶段标签切换 |
| `ToolDispatch`（`Partial=true`） | 工具卡片**立即出现**："正在调用 port_scan"（无需等完成） |
| `ToolResult` | 工具卡片更新：结果摘要/耗时(ms)/错误 ✅ |
| `Text` / `Reasoning` | 流式输出区实时追加（按 task 过滤） |
| `GuardianAssessment` | 显示安全审查徽标（guardian 模型审查中） |

### 10.3 前端面板设计（复用 EduShield UI 扩展）

```
┌─ Agent 状态墙 ──────────────────────────────┐
│ 🟢 pentest（渗透）  task T1  阶段: service_enumeration
│    ├─ ▶ port_scan 运行中…                     │
│    └─ ✅ dns_enum  完成 (1.2s)                │
│ 🔴 logaudit（审计） task T2  等待审批          │
└──────────────────────────────────────────────┘
┌─ 流式输出区（按 task 过滤，自动滚动）─────────┐
│ [T1] 发现 443/tcp open https…（实时追加）      │
└──────────────────────────────────────────────┘
```

- 前端用 `EventSource('/api/stream')` 一条连接；按 `task_id` 分标签页
- Agent 状态卡片：`domain` + 当前阶段 + 最近工具（运行中/完成/失败/待审批 四态）
- 现有 `setInterval(health, 15000)` 轮询保留（健康检查），实时面板改用 SSE（替换结果区的一次性 fetch）

### 10.4 落地成本

| 项 | 工作量 | 说明 |
|---|---|---|
| EventHub（聚合+标注） | ~150 行 | 每部件一条订阅，事件补 task_id/domain |
| `GET /api/stream` | ~50 行 | SSE 端点 + 订阅分发 |
| 前端实时面板 | 中 | Agent 卡片 + 流式区 + EventSource 客户端（参考 reasonix 自带前端消费 /events 的实现） |
| reasonix 侧改动 | **0** | 事件流原生信息已足够 |
