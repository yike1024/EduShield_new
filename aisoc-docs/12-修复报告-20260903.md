## Bug 1：AISOC 4 个 agent 显示离线

### 现象

前端进入 AISOC 后，pentest / logaudit / intel / incident 4 个 agent 一律灰色（offline）。浏览器日志显示前端每 8 秒对 `8786/8788/8789/8090` 发 `fetch no-cors`，2 秒后全部返回 `AbortError: signal is aborted without reason`。

### 根因

[`desktop/frontend/src/components/AisocDashboard.tsx`](desktop/frontend/src/components/AisocDashboard.tsx) 原来有一个 probe `useEffect`：

```typescript
useEffect(() => {
  const targets: Array<{ domain: string; host: string; port: number }> = [];
  if (registry) {
    for (const p of registry) targets.push({ domain: p.domain, host: p.host, port: p.port });
  }
  const tirPort = agentsStatus?.services?.tir?.port ?? 8090;
  if (!targets.some(t => t.domain === 'incident')) {
    targets.push({ domain: 'incident', host: '127.0.0.1', port: tirPort });
  }
  // ...
  const tick = async () => { /* fetch /api/health for each */ };
  void tick();
  const id = window.setInterval(() => { void tick(); }, 8000);
  return () => { /* cleanup */ };
}, [registry, agentsStatus]);
```

它每 8 秒对每个部件端口发一次 `/api/health`，结果写进 `partsHealth: Record<string, boolean>`；在 `domainStates` 里 `partsHealth[d] === false` 强制覆盖为 `'off'`。

caoyike 这台机器只跑 3000（前端代理），不跑大脑（6657 是 linyuxuan）、不跑部件（8786/8788/8789/8090），探测必然超时 abort → 全部 false → 全部显示灰色。

### 改法

1. **删除 `useEffect` 探活块**（原 ~686–736 行）。
2. **删除 `partsHealth` state 声明**（原 ~651–656 行，5 行注释 + `useState<Record<string, boolean>>({})`）。
3. **简化 `domainStates` 的两处分支**：
   - `if (d === 'incident')`：去掉 `const probed = partsHealth[d]` 和它的两个分支判断，只保留 `agentsStatus.services.tir` 路径。
   - 普通部件分支：从「3 优先级判断」简化为单行 `out[d] = brainState ? 'ok' : 'warn'`。
4. **`useMemo` 依赖数组去掉 `partsHealth`**。

### 生效

- `npx vite build` 产出 `dist/assets/index-DOr267Yr.js`（11.19 s）。
- 包内 0 次出现 `partsHealth`，0 次出现 `8786/8788/8789/8090`，0 次出现 `/api/health`。
- `serve_frontend.py` 下发的 html 引用的就是新 bundle。
- 新逻辑：

| brain (6657) | registry 有此 domain | 显示 |
|---|---|---|
| 通 | 是 | 🟢 |
| 通 | 否 | ⚫ |
| 不通 | — | 大脑离线，全部 ⚫ |

## Bug 2：chat/stream 文本重复渲染

### 现象

用户在面板里看到同一段文字出现两次：一次在工具卡里（raw 文本），一次在助手消息里（Markdown 渲染）。例：

```
字典爆破失败。尝试其它途径:/proc/self/fd 枚举与 /app 下无扩展名文件:

1 tools

字典爆破失败。尝试其它途径:/proc/self/fd 枚举与 /app 下无扩展名文件:
```

### 根因

从用户提供的 `fetch` 文件（3903 行真实捕获流）分析，reasonix 在输出一个段落时会**先发 N 个增量帧，再额外发 1 帧全量帧**（与 N 个拼接完全一致）：

```
帧 #1-14: 'SEC' 'RET_KEY 未' '在环境' ... ' cookie:'      ← 增量
帧 #15:   'SECRET_KEY 未在环境...检验 cookie:'              ← 全量重复
帧 #16-23: '字典' '爆破' '失败。尝试其它' ... ':'          ← 增量
帧 #24:   '字典爆破失败。尝试其它途径:/proc/self/fd...'     ← 全量重复
```

前端 [`webApiProxy.ts`](desktop/frontend/src/lib/webApiProxy.ts) 的 `case 'answer'` 无脑 `emitEvent({kind:'message', text: frame.text})`，reducer 每次都覆盖 `assistant.text`。用户看到的就是视觉上的"重复"。

另外：
- `AssistantMessage`（[`Message.tsx:917`](desktop/frontend/src/components/Message.tsx)）用 `<Markdown text=item.text>` 渲染 → **"converted"**（Markdown）。
- `ToolCard`（[`ToolCard.tsx:111`](desktop/frontend/src/components/ToolCard.tsx)）渲染 `item.output` → **"pure"**（raw 文本）。

两边对同一字符串各画一次，视觉上看就像重复。

### 改法（去重全量帧）

1. 在 `webApiProxy.ts` 类成员区（`_lastStreamTaskId` 旁）新增：

   ```typescript
   private _lastAnswerText: Map<string, string> = new Map();
   ```

2. 在 `case 'answer'` 内：拿到 `frame.text` 后先查 `_lastAnswerText.get(tabId)`，相等则 `break`（不发 message 事件）；不相等才更新 Map 并 `emitEvent({kind:'message', ...})`。

### 生效

- `npx vite build` 产出 `dist/assets/index-Bsw-WtWu.js`（10.90 s）。
- 包内 `_lastAnswerText` / `lastAnswerText` 5 处引用（声明 + get + set + minify）。
- 浏览器刷新后，重复的全量 answer 帧不再 emit，用户只看到一次文本。

## Bug 3：502 Bad Gateway 流被腰斩

### 现象

`fetch` 文件最后几行：

```
data: {"answer": ...}
data: {"tool_call": ...}

HTTP/1.1 502 Bad Gateway
Server: BaseHTTP/0.6 Python/3.10.12
Date: Thu, 03 Sep 2026 13:25:16 GMT

Proxy error: timed out
```

### 根因

[`serve_frontend.py:74`](serve_frontend.py) 改前：

```python
conn = http.client.HTTPConnection(host, port, timeout=60)
```

上游 60 秒没新字节（brain 在跑推理 + 工具调用循环），`resp.read1(4096)` 抛超时 → `_proxy` 的 `try/except` 兜底 → 写 502 给浏览器，流被砍。

### 改法

[`serve_frontend.py:74-78`](serve_frontend.py#L74-L78)：

```python
# 修复 502：上游 HTTPConnection 原本 timeout=60，brain 长任务经常超过 60s 没字节，
# resp.read1 抛超时 → 代理 raise → 浏览器收 502 Bad Gateway，流被腰斩。
# 改为 3600s（1 小时），与前端 chatStream 空闲 5 分钟 + brain 部件超时一致；
# 浏览器断流后下次 read1 也会因对端关闭而抛 BrokenPipe/ConnectionReset 正常跳出。
conn = http.client.HTTPConnection(host, port, timeout=3600)
```

### 生效

- 重启代理后 `curl http://127.0.0.1:3000/api/health` 返回 `{"status":"ok","service":"aisoc-brain"}`。
- 长任务（哪怕 1 小时）不再被代理 502 腰斩；前端 `IDLE_TIMEOUT_MS = 300_000`（5 分钟）仍是兜底。

## Bug 4（顺手）：`serve_frontend.py` 启动 NameError

### 现象

我重启代理时遇到：

```
File "/home/caoyike/EduShield/DeepSeek-Reasonix/serve_frontend.py", line 1
    n#!/usr/bin/env python3
NameError: name 'n' is not defined
```

### 根因

文件第 1 字节是 `n`（0x6e），导致 shebang 行变成 `n#!/usr/bin/env python3`。Python 不识别为 shebang，整行被当代码，`n` 未定义。先前那个 PID 230759 大概率是用其它途径启动的，没真正加载这个文件。

### 改法

[`serve_frontend.py:1`](serve_frontend.py#L1)：

```diff
-n#!/usr/bin/env python3
+#!/usr/bin/env python3
```

### 生效

- `python3 -c "import ast; ast.parse(open('serve_frontend.py').read())"` → ✓ Python syntax OK
- `python3 serve_frontend.py` 直接启动成功。
