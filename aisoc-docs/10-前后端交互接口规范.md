# 前后端交互接口规范

> 版本：v1.0  
> 适用范围：EduShield 桌面端前端（React）↔ AiSOC 大脑（FastAPI :6657）↔ 各域部件  
> 维护说明：本文档描述前端实际消费的接口契约，后端实现必须严格对齐字段名与类型。

---

## 1. 概述

前端通过两条通路与后端交互：

| 通路 | 传输 | 用途 |
|------|------|------|
| **REST + SSE** | HTTP `POST /api/chat/stream`（SSE 流式） | 对话、任务下发、流式接收推理/工具帧 |
| **Wails 桥接** | `app.xxx()` → Go `App` 方法 | 桌面端原生能力（窗口、工具结果懒加载、设置等） |

浏览器开发模式（端口 3000）下，Wails 桥接降级为内存 mock，REST 通路经 `serve_frontend.py` 反代到大脑 6657。

---

## 2. 对话流式接口

### 2.1 `POST /api/chat/stream`

发起对话/任务，服务端以 SSE（Server-Sent Events）流式返回推理过程与结果。

**请求头**

| Header | 值 | 必填 |
|--------|-----|------|
| `Content-Type` | `application/json` | 是 |
| `Authorization` | `Bearer <token>` | 否（当前大脑未强制鉴权） |

**请求体**

```json
{
  "message": "string，用户输入（必填）",
  "system": "string，系统提示词（可选）",
  "pass_through": "boolean，true=透传 reasonix 原始帧（10 协议），false=简化帧（07 协议，默认）",
  "session_id": "string，前端会话 ID（推荐传 tabId，同一窗口复用）",
  "pipeline": "string，管道名称，如 'data_leak'（可选）",
  "domain": "string，域路由：pentest / logaudit / incident（可选）",
  "target": "string，目标地址/IP（任务意图必填，用于白名单校验）"
}
```

**响应：SSE 流**

每帧格式：`data: {JSON}\n\n`，结束帧：`data: [DONE]\n\n`。

每帧 JSON 为 `ChatStreamFrame` 联合类型，由 `kind` 字段区分。

---

### 2.2 ChatStreamFrame 帧类型

#### 2.2.1 默认模式（pass_through=false，07 协议）

| kind | 字段 | 说明 |
|------|------|------|
| `delta` | `delta: string` | 字符级增量文本 |
| `thinking` | `thinking: string` | 部件推理过程 |
| `tool_call` | `tool: string, args: unknown` | 工具调用开始，`tool` 为工具名（**字符串**） |
| `tool_result` | `tool: string, output: string, exit_code?: number, partial?: boolean` | 工具执行结果，`tool` 为工具名（**字符串**），`output` 为输出内容 |
| `stage_start` | `stage: string` | 阶段开始 |
| `stage_finished` | `stage: string, ok: boolean` | 阶段完成 |
| `task_created` | `task_id: string, domain: string` | 任务已下发 |
| `answer` | `text: string` | 最终回答片段 |
| `report_ready` | `task_id: string, report_url: string` | 报告生成完成 |

#### 2.2.2 透传模式（pass_through=true，10 协议）

| kind | 字段 | 说明 |
|------|------|------|
| `turn_started` | `task_id?: string` | 一轮 turn 开始 |
| `memory_compiler_stats` | `memoryCompiler: object` | 记忆编译统计 |
| `reasoning` | `text: string` | 推理文本（增量） |
| `text` | `text: string` | 正文文本（增量，字符级） |
| `tool_dispatch` | `tool: object` | 工具调用开始，`tool` 为对象 `{id, name, args, readOnly, partial, ...}` |
| `tool_progress` | `tool: object, output: string, partial: true` | 工具流式 partial 输出 |
| `message` | `text: string, reasoning?: string` | turn 结束合并消息 |
| `usage` | `usage: object` | token 用量 |
| `turn_done` | `task_id?: string` | 一轮 turn 结束 |

#### 2.2.3 补充错误帧

| kind | 字段 | 说明 |
|------|------|------|
| `stream_error` | `err: string` | reasonix 流错误（分类不统一，前端统一归并） |

## 3. 工具结果字段映射（关键契约）

> **本节是「bash 输出空白」Bug 的根因所在，后端必须严格遵守。**

### 3.1 `tool_result` 帧字段约定

无论 07 还是 10 协议，工具结果帧必须提供以下字段：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `output` | `string` | **是** | 工具执行输出。bash 命令的 stdout/stderr 全在此字段。**禁止返回 null/undefined，空输出用空字符串 `""`** |
| `exit_code` | `number` | 否 | 进程退出码。非 0 视为错误，前端会标记 `status: "error"` |
| `partial` | `boolean` | 否 | 是否为流式增量（非最终结果） |
| `tool` | `string` 或 `object` | 是 | 07 协议为工具名字符串；10 协议为 `{id, name, ...}` 对象 |

### 3.2 前端消费字段映射

`webApiProxy.onFrame` 将 `ChatStreamFrame` 转换为 `WireEvent`：

```
ChatStreamFrame.tool_result (07协议)
  ├─ tool: string (工具名)
  ├─ output: string  ──┐
  ├─ exit_code: number│  → WireEvent.tool = { id, name, output, err, truncated }
  └─ partial: boolean ─┘
```

转换规则（`webApiProxy.ts` `onFrame`）：

| 源字段 | 目标 WireEvent.tool 字段 | 转换逻辑 |
|--------|--------------------------|----------|
| `frame.tool` (string) | `name` | 直接赋值 |
| `frame.output` | `output` | `frame.output.slice(0, 8000)`（防 DOM 膨胀），`truncated = length > 8000` |
| `frame.exit_code` | `err` | `exit_code !== 0` 时设为 `"exit_code=N"` |
| 自动生成 | `id` | `aisoc-tool-{tabId}-{task_id}-{counter}`，**若 task_id 缺失则为 undefined** |

### 3.3 已修复的 Bug

**问题**：`aisocStreamItems.ts` 原用 `if (t && t.id)` 守卫，当 `webApiProxy` 因 `task_id` 缺失生成 `id=undefined` 时，整条 `tool_result` 被丢弃 → bash 输出空白。

**修复**：
1. `tool_result` 改为先按 `id` 精确匹配，再按「同名 + running 状态」兜底匹配，**永不丢弃输出**
2. `tool_dispatch` 在 `id` 缺失时生成兜底 id
3. 工具项保留已有 `args`（`tool_result` 帧不带 args，不再清空）
4. 新增 `isShell` 标记（bash/bash_output/wait/waitJob/kill_shell），确保走 shell 渲染路径

## 4. 工具结果懒加载接口（Wails 桥接）

### 4.1 `app.ToolResultForTab(tabID, toolID)`

桌面端为节省内存，会将已完成工具的 `output` 归档（`dataArchived: true`），仅在用户展开卡片时懒加载。

**签名**

```typescript
ToolResultForTab(tabID: string, toolID: string): Promise<{ args: string; output: string } | null>
```

| 参数 | 类型 | 说明 |
|------|------|------|
| `tabID` | string | 当前 tab ID |
| `toolID` | string | 工具调用 ID |

**返回**

| 字段 | 类型 | 说明 |
|------|------|------|
| `args` | string | 工具参数字符串 |
| `output` | string | 完整工具输出（未截断） |
| `null` | — | 未找到该工具结果（浏览器模式 mock 固定返回 null） |

**重要约束**

- 浏览器模式（非 Wails）下，前端**不归档**工具 output（`compactArchivedToolItems` 检测 `isWailsRuntime()` 返回 false 时跳过归档），因此不会调用此方法
- Wails 桌面模式下，Go 后端必须实现此方法并从内存/磁盘返回完整输出，否则展开卡片显示空白

## 5. 任务管理接口

### 5.1 `POST /api/tasks` — 创建任务

**请求体**

```json
{
  "domain": "pentest | logaudit | incident",
  "target": "目标地址",
  "description": "任务描述",
  "session_id": "string（可选）"
}
```

**响应** `202 Accepted`

```json
{
  "task_id": "T-20260919-001",
  "status": "pending"
}
```

### 5.2 `GET /api/tasks/{task_id}` — 查询任务

**响应** `200 OK`

```json
{
  "task_id": "T-20260919-001",
  "domain": "pentest",
  "status": "running | approval | completed | failed | cancelled",
  "created_at": "ISO 时间",
  "updated_at": "ISO 时间"
}
```

### 5.3 `GET /api/agents/status` — 部件健康

**响应** `200 OK`

```json
{
  "pentest": { "status": "ok", "port": 8786 },
  "logaudit": { "status": "ok", "port": 8788 },
  "incident": { "status": "ok", "port": 8090 }
}
```

### 5.4 `POST /api/approve` — 审批放行

**请求体**

```json
{
  "task_id": "T-20260919-001",
  "approved": true,
  "comment": "string（可选）"
}
```

## 6. 错误处理机制

### 6.1 HTTP 错误

| 状态码 | 含义 | 前端处理 |
|--------|------|----------|
| 200 | 成功 | 正常解析 |
| 202 | 任务已接受 | 轮询任务状态 |
| 400 | 请求参数错误 | 显示错误详情 |
| 401 | 未授权 | 提示登录（当前未启用） |
| 404 | 资源不存在 | 显示「未找到」 |
| 500 | 服务器内部错误 | 显示「服务异常，请重试」 |

### 6.2 SSE 流错误

- `stream_error` 帧：前端以 notice 形式展示错误文本
- 网络断开：前端自动重连，重连失败提示「连接已断开」
- `[DONE]` 帧：正常结束

### 6.3 工具结果异常

| 场景 | 前端表现 |
|------|----------|
| `output` 为空字符串 | 显示空 CodeViewer，无崩溃 |
| `exit_code != 0` | 卡片标记错误状态，显示 exit_code |
| `output` 超 8000 字符 | 截断显示 + 「已截断」提示，完整内容由 `ToolResultForTab` 加载 |
| `ToolResultForTab` 返回 null | 显示「无法加载工具输出」提示（Wails 模式） |

## 7. 前端环境检测

```typescript
// bridge.ts
export function isWailsRuntime(): boolean
```

- 返回 `true`：运行在 Wails 桌面壳，可调用 Go 后端方法（含 `ToolResultForTab`）
- 返回 `false`：浏览器模式，工具输出必须保留在前端内存，不归档

## 8. 字段一致性检查清单（后端实现必读）

后端返回数据时，确保以下字段**永不返回 null**（用空字符串替代）：

| 接口/帧 | 字段 | 空值替代 |
|---------|------|----------|
| `tool_result` | `output` | `""` |
| `tool_result` | `tool` | `"unknown"` |
| `tool_dispatch.tool` | `name` | `"unknown"` |
| `tool_dispatch.tool` | `args` | `""` |
| `answer` / `message` | `text` | `""` |
| `WireTool` | `output` | `""` |
| `WireTool` | `err` | `undefined`（无错误时不传） |

> **历史教训**：曾因后端把 `output` 字段重命名或返回 null，导致前端按 `t.output` 读取得到 undefined，表现为「bash 输出空白」。对外响应字段属于稳定契约，重命名必须同步修改前端或提供兼容字段。
